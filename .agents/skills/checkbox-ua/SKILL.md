# Checkbox.ua

Работай с Checkbox как с действующей фискальной системой. Поддерживай весь функционал, доступный конкретной организации, но не считай перечень меню постоянным: тариф, роль, включённые модули и обновления Checkbox меняют доступные возможности.

## Начало работы

1. Определи режим задачи: аудит, операторская операция в портале, API/плагин, сверка или инструкция пользователю.
2. Для портала прочитай [capabilities.md](references/capabilities.md). Используй `$browser:control-in-app-browser` и существующую авторизованную сессию. Если вход отсутствует, попроси пользователя войти самостоятельно; не запрашивай пароль, OTP или КЭП.
3. Перед любым изменением в Checkbox прочитай [safe-operations.md](references/safe-operations.md). Открытие страницы не является разрешением на действие.
4. Для API, WooCommerce или собственного плагина прочитай [api-and-woo.md](references/api-and-woo.md) и заново открой актуальную официальную спецификацию.
5. Для KREUL используй этот skill совместно с `$lavka-woo`. Для цепочки WayForPay → Checkbox дополнительно используй `$checkbox-wayforpay-woo`.

## Источники истины

Приоритет:

1. видимое состояние выбранной организации в `my.checkbox.ua` и подтверждённые ответы API;
2. актуальные официальные API Redoc, Checkbox Wiki, журнал обновлений и справка;
3. код и настройки конкретной интеграции;
4. сохранённые заметки и прежние названия меню.

При расхождении не усредняй источники. Зафиксируй различие и следуй более сильному источнику. Даты, сроки КЭП, статусы ДПС, тарифы, формы заявлений, API-поля и налоговые правила всегда перепроверяй.

## Непереговорные правила

- Сначала установи организацию, режим `test/live`, кассу, кассира/печать, статус смены, роль пользователя и требуемый вид операции.
- По умолчанию выполняй только чтение. Перед фискальной, финансовой, регистрационной, доступной пользователям или массовой записью покажи краткий preview и получи явное подтверждение именно этой операции.
- Не создавай продажу до подтверждённого события оплаты. Не создавай возврат до подтверждённого денежного возврата или явно согласованного бухгалтерского основания.
- Не повторяй мутирующее действие после тайм-аута или неизвестного результата. Сначала найди операцию по идентификатору, номеру, времени, сумме и внешней ссылке.
- Не раскрывай и не сохраняй в skill, коде, логах, скриншотах или ответах пароли, PIN, токены, licence key, КЭП/файлы ключей, пароль КЭП, банковские данные и персональные данные покупателей.
- Не загружай, не заменяй и не удаляй КЭП; не создавай API-доступ; не меняй пользователей/права; не подключай эквайринг и не отправляй формы в ДПС без отдельного подтверждения в момент действия.
- Проверяй итог по авторитетному признаку: фискальный номер/статус ДПС, ID чека, ID смены, квитанция заявления или подтверждённый статус интеграции. Наличие toast-сообщения само по себе недостаточно.
- Не выдавай бухгалтерское или юридическое предположение за решение. Налоговую группу, форму оплаты, момент фискализации и исправление ошибочного чека подтверждает владелец/бухгалтер.

## Режимы

### Аудит кабинета

Работай read-only. Собери обезличенный реестр организаций, торговых точек, касс, кассиров, КЭП, смен, интеграций и проблемных статусов. Разделяй **подтверждено**, **вывод** и **нужно проверить**. Не экспортируй персональные данные без необходимости.

### Операторская операция

Найди функцию через живое меню и контекстные действия. Проверь prerequisites, подготовь preview, запроси подтверждение перед последним изменяющим действием, затем сверь результат. Если UI отличается от справочника, не угадывай координаты и не используй скрытые endpoints: исследуй видимые элементы и официальную документацию.

### API или плагин

Предпочитай официальный API для повторяемых семантических операций. Используй портал для регистрации, настроек и функций, не предоставленных API. Реализуй идемпотентность, журнал операций без секретов, dry-run и reconciliation неизвестного результата.

### Сверка

Сопоставляй внешний платёж/заказ, локальную операцию, чек Checkbox и статус ДПС. Несоответствие отмечай как инцидент; не «исправляй» его созданием нового чека без выяснения исхода первого запроса.

## Завершение

Сообщи выбранную организацию и среду без секретов, выполненную или только проверенную функцию, идентификаторы результата в безопасном виде, доказательство итогового статуса и оставшиеся бухгалтерские/операционные решения. Для кода укажи владельца поведения, тесты и rollback/kill switch.
