## Створення: підтверджено документацією

[Базовий save](https://developers.novaposhta.ua/view/model/a90d323c-8512-11ec-8ced-005056b2dbe1/method/a965630e-8512-11ec-8ced-005056b2dbe1)
описує `InternetDocument.save`; JSON-приклад використовує
`modelName=InternetDocumentGeneral`. Не змінювати модель вже працюючих read-методів
лише на підставі назви прикладу. Для нового create-клієнта зафіксувати обраний
контракт у fixtures та перевірити його в окремо дозволеному пілоті.

JSON endpoint: `https://api.novaposhta.ua/v2.0/json/`. Тіло: `apiKey`, `modelName`,
`calledMethod`, `methodProperties`. HTTP 200 може містити бізнес-помилку;
перевіряти `success`, `errors`, структуру `data`, `Ref` і `IntDocNumber`.
Успішна відповідь також містить `CostOnSite`, `EstimatedDeliveryDate`, `TypeDocument`.
`warnings` не прирівнювати до невдалої операції чи підстави повторити `save`.

Основні поля `methodProperties`:

- `PayerType`: Sender / Recipient / ThirdPerson; `PaymentMethod`: Cash / NonCash.
  Підтримка API не означає автоматичного дозволу всіх варіантів нашою політикою.
- `ServiceType`: WarehouseWarehouse / WarehouseDoors / DoorsWarehouse / DoorsDoors.
- `DateTime`: `dd.mm.yyyy`; максимальна майбутня дата — створення + 3 місяці.
  При перевищенні API коригує дату й повертає warning разом з успіхом.
- `CargoType`, `SeatsAmount`, `Description`, `Cost` (оголошена вартість).
- `Weight`: фактична вага у кг, мінімум 0.1. `VolumeGeneral`: м³, мінімум
  0.0004; потрібний, якщо немає `OptionsSeat`.
- Відправник: `CitySender`, `Sender`, `SenderAddress`, `ContactSender`, `SendersPhone`.
- Одержувач у Ref-варіанті: `CityRecipient`, `Recipient`, `RecipientAddress`,
  `ContactRecipient`, `RecipientsPhone`.
- `SenderWarehouseIndex` / `RecipientWarehouseIndex` — цифрові адреси точок,
  не UUID Ref. Не підміняти ними зареєстровану адресу чи Ref без перевірки контракту.

[Створення до відділення рядком](https://developers.novaposhta.ua/view/model/a90d323c-8512-11ec-8ced-005056b2dbe1/method/a19ced79-8f32-11ec-8ced-005056b2dbe1)
використовує `NewAddress=1`, `RecipientCityName`, `RecipientArea`,
`RecipientAreaRegions`, `RecipientAddressName` (номер відділення),
`RecipientName`, `RecipientType`, `SettlementType`, `RecipientsPhone`.
Для відділення `RecipientHouse` і `RecipientFlat` не заповнюють.
`SettlementType` береться з адресного довідника, не вгадується з назви міста.
Не переносити до цього варіанта Ref-поля з іншого прикладу без підтвердження.

## Поштомат і коробки

[Окремий контракт поштомата](https://developers.novaposhta.ua/view/model/a90d323c-8512-11ec-8ced-005056b2dbe1/method/0227072e-8f38-11ec-8ced-005056b2dbe1)
у текстових правилах дозволяє Parcel / Documents, лише одне місце, до 20 кг,
ширину 40 см, довжину 60 см, висоту 30 см та оголошену вартість до 29 000 грн.
Це загальні обмеження документації на дату перевірки, а не заміна актуальної
картки конкретної точки. Майбутній preflight має перевіряти обидва джерела;
розбіжність не означає дозвіл застосувати м'якшу межу.

`OptionsSeat` — масив місць: `weight` у кг; `volumetricWidth`,
`volumetricLength`, `volumetricHeight` у см; `volumetricVolume` у м³.
Розрахунок об'єму з наших сантиметрів: `length * width * height / 1000000`.
Це об'єм, не об'ємна вага. Не передавати см³ як м³.

**Розбіжність джерела:** JSON-приклад цієї ж сторінки містить Cargo та два місця,
хоча текст прямо забороняє їх для поштомата. Приклад не є валідною тестовою
відправкою. Не копіювати його дослівно; застосовувати суворі текстові правила та
перевіряти прийнятність payload перед дозволеним пілотом.

## Друк: підтверджено документацією

[Маркування](https://developers.novaposhta.ua/view/model/a3fe2fdd-8512-11ec-8ced-005056b2dbe1/method/a40fb782-8512-11ec-8ced-005056b2dbe1)
повертає форму за Ref або номером ТТН. Шаблони серверних URL, лише placeholders:

```text
https://my.novaposhta.ua/orders/printMarking85x85/orders[]/{REF}/type/pdf8/apiKey/{KEY}
https://my.novaposhta.ua/orders/printMarking100x100/orders[]/{REF}/type/pdf/apiKey/{KEY}/zebra
```

Перший — A4 (6 наклейок), другий — Zebra. Для пакетної печаті документація
вказує типову межу 100 маркувань і параметри `limit` / `page`.

**Проєктне рішення безпеки, ще не реалізоване:** URL з ключем формує тільки сервер.
Не показувати його в HTML, редиректі, листі, браузері або логах. Потрібний власний
авторизований endpoint: capability + nonce + належність shipment замовленню,
allowlist хоста/формату, таймаут/межа розміру, перевірка MIME та PDF-сигнатури,
заборона довільних редиректів і приватна видача без кешування.
Зовнішні ТТН клієнта не отримують права на друк через ключ магазину.

## Трекінг: підтверджено документацією

[getStatusDocuments](https://developers.novaposhta.ua/view/model/a99d2f28-8512-11ec-8ced-005056b2dbe1/method/a9ae7bc9-8512-11ec-8ced-005056b2dbe1)
описаний для `TrackingDocument`, JSON-приклад — `TrackingDocumentGeneral`.
`Documents` містить `DocumentNumber` і, за потреби розширених даних, `Phone`;
до 100 документів у запиті. API-ключ і успішна валідація потрібні для повних
даних. Неавторизований результат не є доказом особи відправника/одержувача.

Значення кодів, потрібні для наступної реалізації:

| Коди | Значення за документацією | Проєктне трактування повідомлення |
|---|---|---|
| 1 | Накладна створена, вантаж ще не переданий | Лише «підготовлено», не «відправлено» |
| 2 / 3 | Видалена / номер не знайдено | Не надсилати повідомлення про відправку |
| 4 / 41 / 5 / 6 | Вантаж у логістичній мережі / прямує між містами | Свідчення фізичного руху, а не самого створення |
| 7 / 8 | Прибуття до відділення / поштомата | Вантаж уже переданий перевізнику |
| 9 / 10 / 11 | Отримано; варіанти стану грошового переказу | Доставлено; не підтвердження нашого банківського платежу |
| 101 | Доставка до одержувача | Фізичний рух |
| 102 / 103 / 104 / 105 / 106 / 107 / 111 / 112 / 124 | Відмова, зміни, повернення або інші спеціальні стани | Окрема обробка, не універсальне «відправлено» |

Повідомлення — наш висновок із офіційних значень, не готовий алгоритм у релізі.
Невідомий код зберігати як невідомий; не вважати будь-який код > 1 успішною
відправкою. Зберігати час перевірки; помилка нового опитування не доводить
скасування чи доставки. Дедуплікація сповіщень потрібна окремо від polling.

## Невідомий результат створення

[getDocumentList](https://developers.novaposhta.ua/view/model/a90d323c-8512-11ec-8ced-005056b2dbe1/method/a9d22b34-8512-11ec-8ced-005056b2dbe1)
дозволяє пошук за `DateTime` / `DateTimeFrom` + `DateTimeTo` або `IntDocNumber`.
Без дати й номера повертає поточний день. `GetFullList=1` обмежений 100 записами;
для повної вибірки потрібні `GetFullList=0` і `Page` (до 100 на сторінку).
Відповідь містить Ref/номер, дати, міста/адреси, вагу, кількість місць, вартість,
платника та `StateId` / `StateName`.

У перевірених сторінках не підтверджено carrier-side idempotency key чи пошук за
нашим UUID. Локальний ключ не гарантує дедуплікацію на боці НП. Після timeout:
залишити `unknown`, не повторювати `save`; список може бути джерелом для ручної
звірки, але не доказом відсутності ТТН. Збіг дати/міста/суми сам по собі не дає
права автоматично прив'язати чужу накладну.

## Залишається реалізувати / уточнити

- Детермінований payload з order-only одержувачем, фактичними коробками,
  підтвердженим sender mapping, оголошеною вартістю та політикою платника.
- Узгодити розбіжності прикладів: назви моделей з `General`, оголошена вартість
  за замовчуванням 300.00 / 300.01, обов'язковість організаційних полів у
  PrivatePerson-прикладі. Не використовувати defaults замість явної вартості.
- Окремо перевірити адресний варіант і COD-контракт; кілька складів з COD
  залишаються забороненими до погодженого правила. Не припускати, що наявність
  `AfterpaymentOnGoodsCost` у відповіді означає право створити будь-який COD.
- Durable claim, unknown-outcome recovery, серверний PDF, polling, кабінет,
  service email/Telegram і локальні mocked-тести. Наявність документації не
  вмикає ці функції та не замінює їх тестування.
- Реальний пілот, write flags та deployment — лише після окремого дозволу.
