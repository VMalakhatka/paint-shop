## Детальные строки: контракт для параллельного frontend

Сохранить существующие `expenses`, `cities`, `masterClass`, `controls`, `inputs`.
Добавить `expenseLines` в summary И audit. Ниже согласуемая структура,
на которую сейчас будет рассчитан фронт; при необходимости изменения сообщить
в исходную задачу до окончания работы.

```json
{
  "expenseLines": [{
    "lineId": "ODESA_SALARY_DOCUMENTS",
    "sortOrder": 30,
    "city": "ODESA",
    "category": "SALARY",
    "label": "Зарплата по документам",
    "documentCount": 12,
    "amount": "66770.67",
    "profitImpact": "66770.67",
    "accountingTreatment": "OPERATING_EXPENSE",
    "source": "FOLIO",
    "filters": {
      "expenseCodes": ["З/П ОДЕС"],
      "operationTypes": ["РАСХОДЫ ОДЕССЫ"],
      "purposeCodes": [],
      "cashWarehouseIds": [],
      "bankWarehouseIds": [],
      "cashWarehouseMode": "ALL",
      "bankWarehouseMode": "ALL",
      "operationRequired": false,
      "note": "Источник информации зп — контрольный признак, не обязательный фильтр"
    }
  }],
  "periodPolicy": {
    "candidateFrom": "2026-06-01",
    "candidateToExclusive": "2026-09-01",
    "explicitPeriodPriority": true,
    "description": "Правило периода всех расходов и диагностика ошибок"
  }
}
```

Числа денег — decimal strings; нулевые/ручные строки должны быть в справочнике
expenseLines даже без документов. `ALL`+[] = все склады, `INCLUDE`+ids = только,
`EXCLUDE`+ids = кроме; cash/bank раздельно. Пустые purposeCodes = любой.
`operationRequired` показывает, применяется ли тип как обязательное условие.
`filters.note` — безопасное пояснение правила, не сырое примечание платежа.

Строки не должны дублировать агрегаты: сумма их profitImpact по городу =
city.operatingExpenses, кроме отдельно обозначенных нерешённых сумм.
Нужен стабильный lineId у документов (`expenseLineId`) для детализации без
повторной классификации фронтом.

Минимум отдельных строк:

- Киев: АРЕНДАКИ, АРЕНДАКО; коммунальные; зарплата UAH; зарплата RUB→UAH;
  ручные допработы; БАНКОВСК; налоговая доля MALAFOP; KONDFOP;
  НЕРЕГ КИ; бухгалтер; НЕРЕГУЛ; реклама; транспорт Украина;
  импортный транспорт с impact0; интернет; ТЕЛЕФОНК; ТЕЛЕФКАЛ.
- Одесса: аренда; коммунальные; зарплата по документам; ручная доплата;
  БАНКОВСК; доля MALAFOP; KONDFOP с0; НЕРЕГМИХ и НЕРЕГДОН отдельно;
  НЕРЕГУЛ; реклама; транспорт; интернет; телефон.
- МК: income/returns/net/base/adjustment отдельными полями masterClass как сейчас,
  они не операционные расходы. Накладные в masterClassDocuments.

Точный финальный контракт находится в Java `docs/api/FOLIO_PROFIT_REPORT_API.md`.

Фронт 0.3.0 проверен на синтетическом ответе реального DTO/service-теста Java:
32 стабильные строки, вложенные periodDiagnostics, decimal strings и controls.
`periodDiagnostics` = `{document, status, reason, includedInTotals, amountTreatment}`;
`OUTSIDE_REPORT_MONTH` — штатное исключение. Проблемный платёж находится в этом
реестре и не дублируется в обычном `documents`. Для сохранённого предварительного
влияния используется `LEGACY_PROVISIONAL_INCLUDED`, для исключённого — `EXCLUDED`.

Новые controls: `periodDiagnosticCount`, `periodProblemCount`,
`provisionalDocumentCount`, `provisionalDocumentAmount`,
`provisionalOperatingExpenseTotal`. Они описывают весь набор до усечения.
Общие налоговые документы связаны с городскими строками через `expenseLineIds`.
`sourceInfo` — очищенная короткая метка, `periodNote` — извлечённые маркеры,
не сырой комментарий. Все денежные значения API — decimal strings.

Архив проверен по SHA256 всех 17 копий и целостности ZIP. Production-деплой
и изменения ФОЛИО в рамках этого задания не выполнялись. Распределение
405 грн, спорная разница Киева 2,08 грн и список строгих статей остаются открытыми.
