# Полная синхронизация: поставщик и контрольная сумма

Проверено: 2026-10-22, Java unit-тесты без живого контекста и временные товары
на `paint.local`. Production не изменён, полный живой прогон не запускался.

## Что изменено

Java читает поставщика карточки ФОЛИО из `SCL_ARTC.DOP2_ARTIC` на том же складе 7,
который служит источником полной карточки. Плагин `lavka-total-sync` 0.1.2
получает имя и назначает существующий термин `product_brand` либо создаёт новый.
Связь обновляется и для новых, и для существующих товаров. Пустой поставщик в
ФОЛИО снимает старую связь. Отсутствующее поле в запросе старой Java ничего не
меняет. Неизвестный результат чтения источника не считается пустым поставщиком.

Настройка `psu_catalog_suppliers`, её галочки и порядок не изменяются. Для уже
разрешённого поставщика товар после назначения попадает в существующий фильтр и
получает строку поставщика в карточке. Новый поставщик по-прежнему скрыт до
разрешения менеджером. Название поставщика не является доказательством бренда
производителя для Google. Пользовательские действия и справка каталога прежние.

Новый SHA-256 охватывает все поля экспортируемой карточки, кроме самого hash,
включая поставщика. Формат `_ms_hash` остаётся 64 hex-символа; содержимое хеша
версионировано. Первый полный проход после обновления повторно обработает
карточки со старым хешем. Дальше изменение поставщика или другого передаваемого
поля вызывает update; неизменённая карточка пропускается.
Цены, остатки, галерея отдельной media-синхронизации и настройки витрины не входят
в этот контракт. Ручное изменение Woo при неизменной ФОЛИО не меняет source hash.

## Порядок выпуска

1. Согласовать окно полной синхронизации и резервную копию Woo. Проверить, что
   общая ecosystem-очередь свободна; не запускать второй параллельный sync.
2. Задеплоить `lavka-total-sync` 0.1.2 первым. Новый плагин совместим со старой
   Java; для уже активного плагина повторная активация или миграция не нужны.
3. Собрать и задеплоить Java-коммит этой задачи. Java проверяет поддержку поля
   через OPTIONS Woo API до первой diff-порции. При старом PHP будет явная ошибка
   `WOO_FULL_SYNC_SUPPLIER_UNSUPPORTED`, без ложного подтверждения нового хеша.
4. Запустить штатную полную синхронизацию с начала, не с сохранённого хвостового
   курсора. Первый проход может быть длиннее обычного из-за новой версии хеша.
5. Сверить `P-141515`: поставщик в ФОЛИО, связь `product_brand` в Woo, включённый
   показ поставщика, строка на карточке и отбор по нему. В отчёте не должно быть
   ошибок. Проверить повторный проход без изменений и изменение поставщика на
   согласованном тестовом товаре, не изменяя ради теста живую карточку клиента.

Не считать HTTP 200 успехом всей порции: Woo может вернуть ошибки отдельных
товаров. Java выводит безопасные коды ошибок и считает только подтверждённые
успехи, не повторяя уже успешные товары при таком ответе. При ошибке создания
термина прежний хеш остаётся; если связь не прошла проверку после сохранения,
`_ms_hash` снимается, чтобы следующий проход повторил карточку.

Откат: остановить full sync и вернуть согласованную пару версий Java/PHP.
Откат кода не отменяет назначенные связи и созданные термины; восстановление
данных требует отдельного решения. Не удалять поставщиков и не сбрасывать
галочки видимости массово. Глобальный lock и транспортный retry/bisect не менялись.

## Проверки и владельцы

- Java: `CardTovExportDaoImpl`, `CardTovExportService`, `FullSyncHash`,
  `SyncServiceImpl`, `WooApiClient`; точный контракт в Java-репозитории:
  `docs/api/FOLIO_FULL_SYNC_SUPPLIER_HASH.md`.
- WordPress: `lavka-total-sync/inc/supplier-sync.php`; запись выполняется через
  Woo CRUD, в обычном защищённом Woo REST. Legacy PHP-upsert использует тот же
  helper. Новых публичных write endpoints и новых настроек нет.
- Локально: `wp eval-file wp-content/plugins/lavka-total-sync/tests/supplier-sync-local.php`.
  Тест допускает только `paint.local`, создаёт собственные временные товары и
  термины, удаляет их в `finally`. Проверяет создание/смену/очистку, старый payload,
  права, ошибки до/после сохранения, hash и неизменность настроек, цен и остатков.
- Java 17: `FullSyncHashTest`, `CardTovSupplierTest`,
  `SyncServiceUnitAttributeTest`, `WooUnitAttributeClientTest`. Не запускать
  общий интеграционный application context против живой ФОЛИО ради этой проверки.
