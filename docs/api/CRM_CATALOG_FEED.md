# Персональный закупочный XML для CRM

Проверено: 2026-11-17, локальный код, offline lifecycle/endpoint tests и UI fixtures.
Владелец: `pc-order-import-export`, `CrmCatalog*`. Production-деплой, подготовка
файла конкретного клиента и реальный импорт SalesDrive этим документом не подтверждаются.
Пользовательский маршрут: [оптовая инструкция](../WHOLESALE_CUSTOMER_GUIDE_UK.md#crm-catalog).

## Назначение и границы

Отдельная выгрузка закупочных цен текущего оптового пользователя. Несколько
брендов `product_brand` объединяются по OR. Складские группы выбираются из тех же
торговых location, что использует `PriceList::location_ids()`. Состав определяется
`lavka_get_locations_mapping_for_java()`, пересечение кодов ФОЛИО запрещается,
чтобы не считать один склад дважды. Группа «Київ» включает склады ФОЛИО из общей настройки сайта — одной для всех
клиентов. Персонального состава складов у CRM-выгрузки нет. Отдельного live-запроса к ФОЛИО нет.
Нельзя обещать остаток одного физического склада из уже агрегированной группы.

Используется `PartnerCatalogData::build_ids()` с клиентским `BroadcastPricing::scope`,
проверкой публичности/пароля/категорий и выбранными locations. Варианты наследуют
бренд родителя. С 22.11.2026 XML SalesDrive и Prom и колонка `Brand` в партнёрских
XLSX/CSV используют назначенные термины WooCommerce `product_brand`. В файле видны
названия, открытые для витрины в `psu_catalog_suppliers`. Несколько названий
перечисляются через запятую. Если публичного бренда нет, товар, прошедший отбор,
сохраняется с пустым полем в таблице и без тега `vendor` в XML. Формы партнёрского каталога и CRM предлагают только открытые бренды.
CRM учитывает оставшиеся открытые бренды прежнего выбора. Если все скрыты,
нужно выбрать открытый бренд заново. Скрытие бренда делает прежние файлы с ним
недоступными по ссылке до формирования актуального файла. Для Prom выбор скрытого
бренда также требует пересмотра. При отборе только по SKU или категории отсутствие
открытого бренда сохраняет товар в выдаче.
Источник и владелец назначения
описаны в [модели данных](../BACKEND_GUIDE.md#lavka-catalog-brand).

Закупочная цена берётся из тех же Woo pricing hooks, что и прайс
клиента; название роли не служит подтверждением индивидуального договора ФОЛИО.
Нулевые/неизвестные остатки остаются в файле как ноль, чтобы CRM могла снять наличие.
С 19.11.2026 артикул без действующей закупочной цены сохраняется в XML со всеми доступными данными. Кабинет показывает количество таких товаров. Скрытые товары
и внутренние supplier-атрибуты не выдаются. Java packaging и загрузка фото не вызываются:
передаются публичные URL изображений, до 10 на товар, единица и публичные характеристики.

Это не смена формата `pcoe_partner_feed`: Prom остаётся розничным, лимит 500 и его
настройки/ключ не меняются. CRM не отправляет заказов и не пишет остатки, платежи,
профили, медиа или документы ФОЛИО. Нет автоматической отправки ссылки клиенту.

## Маршрут и разрешения

`Мій кабінет → Дані та фото для вашого сайту → Закупівельний прайс для CRM / SalesDrive`.
Сам клиент выбирает бренды/группы, готовит и проверяет XML. Отдельная галочка разрешает
доступ к закупочным ценам, после чего включается ссылка. Нет скрытого включения
при сохранении, публикации или скачивании файла. Менеджер не получает эти цены
через подмену customer_id в URL; отдельного редактора чужой CRM-добірки пока нет.

POST `admin-post.php?action=pcoe_crm_catalog`: nonce `pcoe_crm_catalog`, текущий
пользователь, общая wholesale role gate. Действия `save`, `retry`, `enable`,
`disable`, `rotate`, `download`. Названия соответствуют кнопкам интерфейса.

GET `admin-post.php?action=pcoe_crm_feed&user=…&key=…`: без cookies и входа,
но с персональным bearer key. Ключ HMAC с отдельным префиксом `crm-purchase`,
user ID, случайным seed и auth salt сайта. Ключ Prom не принимается. Адрес
сохраняется при обычном обновлении данных и save; save выключает доступ до новой
проверки. Rotate отзывает старый адрес; изменение auth salt тоже отзывает его.
Role gate проверяется на каждом чтении. Удаление пользователя очищает снимки/cron.

200 выдаётся только для полного файла, не старше двух часов, с совпадающими revision
и pricing/warehouse context. 403 — ключ/роль/выключенный доступ. 503 и Retry-After —
нет готового актуального файла, busy или нарушена целостность. Это не пустой успешный
каталог: потребителю нужно сохранить прежний импорт. `no-store` через WP nocache,
noindex, nosniff, no-referrer. Нельзя помещать полный URL в логи, документы и примеры.

## Формат и настройка SalesDrive

YML: `yml_catalog/shop/offers/offer`. Стабильный `offer/@id` = Woo product/variation ID.

| XML | Значение |
|---|---|
| `vendorCode` | Артикул сайта |
| `barcode` | EAN/GTIN при наличии, строка с сохранением ведущих нулей |
| `price`, `purchase_price` | Одна и та же закупочная цена этого клиента. Оба тега отсутствуют, если цена не задана, равна нулю или недопустима |
| `retail_price` | Регулярная розничная цена сайта, если доступна, в том числе у товара без закупочной цены |
| `purchase_price_status` | `unavailable` у позиции без действующей цены. Количество товара сохраняется независимо от цены |
| `currencyId` | Валюта магазина |
| `quantity_in_stock` | Неотрицательное количество выбранных групп, неизвестное = 0 |
| `available` | true только при положительном известном количестве |
| `name`, `name_ua` | Текущее название, без автоматического перевода |
| `description`, `description_ua` | Описание без HTML, без автоматического перевода |
| `categoryId`, `categories` | Реальные Woo ID и иерархия |
| `picture`, `param`, `vendor`, `url` | Публичные фото/характеристики/бренд при наличии/карточка |

Публичная регулярная розничная цена сайта передаётся отдельным полем `retail_price`, когда она известна. Для закупки используют только `purchase_price` или `price`. `selling_type=w`. `price` в этом supplier-прайсе нельзя
настроить как цену продажи клиента. Для SalesDrive проверить маппинг именно на
закупочную стоимость, артикул и фактическое количество, не подмену available на 1000.
Если текущий XML-импорт CRM не позволяет назначить поле закупочной стоимости,
согласовать с поддержкой SalesDrive альтернативное сопоставление; не обещать
автоматическое заполнение себестоимости без пилота. Остатки поставщика следует
отделить от собственного склада клиента. Отсутствие товара в изменённой добірке
не является самостоятельной командой удаления карточки.

Первичные источники, просмотрены 2026-11-17:
- [SalesDrive: XML-импорт и сохраняемые поля](https://salesdrive.ua/blog/xml-import-products-dont-update-fields/)
  и опубликованный скриншот подтверждают настраиваемые блоки offers/offer и маппинг.
- [Каталог товаров](https://salesdrive.ua/features/product-catalog/) подтверждает
  штрихкод, себестоимость, остатки и Excel/YML-импорт; это не полный XML-контракт.
- [Импорт наличия условным количеством](https://salesdrive.ua/blog/import-yml-status-available/)
  описывает настройку 1000 при available. Для данного файла нужна реальная quantity.

## Подготовка и хранение

User meta `_pcoe_crm_catalog`: selection, enabled, seed, revision.
Опции `pcoe_crm_build_USER`, `pcoe_crm_snapshot_USER` и
`pcoe_crm_GENERATION_INDEX_USER` приватны, autoload=false. В них нет публичного
upload URL. Части XML сохраняются по 100 записей, SHA-256 проверяется при чтении.
До ответа файл собирается в защищённом системном temp-файле и удаляется после чтения.

«Оновити стан CRM-файлу» открывает кабинет отдельным GET с новым параметром
`pcoe_crm_status` и возвращает к секции CRM. Статус принадлежит текущему
пользователю. Ссылка обновления только перечитывает состояние.
Владелец может скачать актуальный XML для проверки до включения ссылки.
Кабинет, фоновая сборка и обработчик скачивания получают список открытых
брендов по одной настройке видимости и публичному счётчику WooCommerce
`product_count_product_brand`. Служебный счётчик WordPress может включать
скрытые товары и давать другой список в `admin-post.php`.

Cron `pcoe_crm_catalog_tick` использует named lock на пользователя для сборки файла.
Это чтение данных Woo, а не синхронизация остатков: не запускает Java/ФОЛИО,
не меняет складскую проекцию и не добавляет глобальный sync lock.
Keyset query `ID > after`, максимум 15 секунд между контрольными точками, без OFFSET.
30 000 просканированных записей или 30 МБ дают явную ошибку, без обрезания.
Одна часть ограничена 2 МБ. Полная подготовка ограничена часом.

Recovery event ставится до чтения: авария повторяет последний пакет с тем же
generation/index. Снимок публикуется одной заменой указателя только после всех
частей. Повтор после аварии между публикацией и очисткой не удаляет свою generation.
Во время обычного refresh старая полная версия может обслуживаться до двух часов;
смена брендов/складов выключает ссылку и удаляет старую версию. Новый снимок может
содержать данные, прочитанные в разные моменты подготовки, это не транзакционный
снимок ФОЛИО. Возможен один остаточный приватный набор chunks при аварии ровно после
переключения версии и до удаления старой; автоматический общий garbage collector
пока отсутствует.

После включения следующая подготовка планируется через 30 минут после завершения.
Это не гарантия обновления каждые 30 минут: нужны исправный WP-Cron/системный cron
и доступная сборка файла этого пользователя. Failed требует явного retry. Изменение ценовой роли или
общего маппинга не позволяет читать старый снимок; очередной worker автоматически
пересобирает его с новым контекстом (включая начатую подготовку). При неизвестной ошибке UI не печатает SQL.

## Проверка, выпуск и откат

Offline tests: `tests/crm-catalog.php`, `tests/crm-status-refresh.php`, `tests/partner-catalog-data.php`, существующие
`tests/partner-catalog.php` / `tests/partner-catalog-access.php`. UI fixture проверяет
desktop/mobile. Проверить nonce/role/HTTP lifecycle, 605 позиций, цену/баркод/количество,
закрытие доступа, целостность снимка и восстановление после публикации.

Обычный WordPress-деплой существующего плагина и MU-help. Новых плагинов, Java,
миграции схемы, активации или rewrite flush нет. До пользовательского save фоновые
задачи и ссылки не создаются. После деплоя нужен разрешённый пилот: выбрать реальные
бренды и существующую группу «Київ», проверить первые товары с прайсом кабинета,
скачать XML, явно включить ссылку и проверить импорт в SalesDrive. Не включать
ссылку за клиента молча. Фактическую production-проверку фиксировать отдельно.

Откат конкретного клиента — Pause CRM link. Откат функции — отключить
`CrmCatalog::hooks()` и вызов `CrmCatalogUi::render()` (совместно). Приватные опции
не становятся публичными при откате. Не удалять общие Prom-настройки и role gate.
