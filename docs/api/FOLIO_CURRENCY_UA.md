# Валютная цена Украина — управление через сайт

Проверено кодом и локальными тестами: 2026-10-22. Владелец UI: `lavka-price-sync/inc/folio-currency.php`, чтения файлов — `folio-currency-import.php`. Java: `FolioCurrencyPriceController`, `FolioCurrencyPriceService`, `FolioCurrencyPriceDao`; точный backend-контракт — `kreul_com_ua/docs/api/FOLIO_CURRENCY_UA.md`.

Статус: реализация подготовлена локально; production не опубликован, живые UPDATE в этой задаче не выполнялись. Браузерный сценарий проверен на изолированном стенде с реальными PHP/JS и искусственными ответами Java. Проверка реального WordPress в браузере остановилась на форме входа.

## Подтверждённая логика

22.10.2026 владелец подтвердил перенос действий макроса Access «Валютная Цена Украина» без изменения бизнес-логики и разрешил объединить их в одну операцию менеджера. Источник — `Запросы-TS.mdb`, каталог `$folio-access-catalog`.

1. Для каждого CODE_ARTIC: обновить `dbo.SCL_ARTC.CENA_VALT=PRICE`, `COD_VALT=KOD_VALUT` **на всех складах**.
2. Затем обновить `dbo.SCL_PRIC.RUB_PRICE=PRICE` только при `NAME_PRICE='ЯЯ_Р_ВАЛЮТ' AND ID_SCLAD=7` для тех же артикулов.

Обе части выполняются в одной транзакции MS SQL. Условия и значения совпадают с сохранёнными запросами; никаких пересчётов наценки, конвертации валюты или обновления цен WooCommerce нет. Новые карточки и цены не создаются. Отсутствующие строки пропускаются, как в исходных UPDATE, и видны в отчёте.

## Действия менеджера

Каноническая короткая инструкция: [Менеджеру: «Валютная цена Украина»](../FOLIO_CURRENCY_MANAGER_RU.md). После публикации: **Лавка ФОЛИО → Валютная цена Украина**; доступ — `manage_lavka_prices`.

`folio-currency-help.php` выводит краткую инструкцию с примером и четыре раскрывающиеся подсказки рядом с загрузкой, просмотром, подтверждением и проверкой статуса. Домен `lps-currency`, украинский/русский переводы. Открытие справки не делает запросов к Java/ФОЛИО. Подготовлено локально 22.10.2026, production-публикация справки не выполнялась.

## Контроль и восстановление

Предпросмотр только читает MS SQL. Применение повторно сверяет полный набор строк и исходные значения под блокировками: изменение после просмотра даёт STALE до UPDATE. Обе части используют один `mssqlTransactionManager`, общий с учётными ценами mutex и общий WordPress ecosystem lock. Неизвестный итог удерживает WordPress lock до его обычного срока 10 минут; снятие блокировки само по себе не подтверждает результат.

В WordPress сохраняются пользователь, имя и SHA-256 файла, время, входные значения, исходные строки, ответ Java и итоговый снимок. Исходный файл не попадает в Media Library. Аудит хранится в неавтозагружаемых options `lps_currency_job_<uuid>`, одноразовая отправка — `lps_currency_claim_<uuid>`, последние 50 ссылок пользователя — `lps_currency_history_<user>`. Старые записи аудита автоматически не удаляются.

PREVIEW действует 15 минут; Java хранит токены/результаты в памяти до 24 часов, максимум 100 операций до очистки устаревших. После перезапуска Java старый токен не восстанавливается и не разрешает повторную запись. Успешно сохранённый в WordPress итог остаётся доступен. UNKNOWN означает необходимость проверить текущие строки ФОЛИО и сохранённый аудит администратором; не загружать файл повторно до выяснения результата.

Общий предел — 5000 затрагиваемых строк. Java проверяет Paint_Ua, типы/длины ключевых колонок и отсутствие триггеров на двух таблицах. Несоответствие останавливает операцию; схема и права автоматически не меняются. Сервисному пользователю нужны SELECT метаданных/затрагиваемых таблиц, UPDATE указанных полей и существующий доступ к `sp_getapplock`. Не выдавать db_owner ради этой функции.

Откат ошибочного файла после успешного сохранения — отдельная согласованная операция администратора по исходному снимку и актуальным данным; кнопки автоматического обратного UPDATE нет. При ошибке до commit транзакция откатывается; потерю связи во время commit считать UNKNOWN до проверки.
