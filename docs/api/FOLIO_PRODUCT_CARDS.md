# Чтение карточек ФОЛИО: первая функция меню «Лавка ФОЛИО»

Владелец интерфейса: `lavka-price-sync/inc/folio-product-cards.php`, XLSX:
`folio-product-cards-xlsx.php`. Владелец SQL: Java `FolioProductCardDao`;
защищённый POST `/admin/folio/product-cards/read`, точный backend-контракт —
`kreul_com_ua/docs/api/FOLIO_PRODUCT_CARDS_API.md`.

Проверено по исходным Access MSysQueries, Excel и архивному определению card_tov:
2026-10-18. Access-файл и Excel — источники структуры, их макросы не исполняются.

Менеджер с `manage_lavka_prices` открывает **Лавка ФОЛИО → Карточки товаров**,
выбирает один из двух запросов или их сравнение и вводит артикулы по одному в
строке. Все подходящие карточки Paint_Ua выбираются отдельным режимом. Чтение показывает
первые 50 строк, количество всех возвращённых строк и отсутствующие в результате
артикулы. Выгрузка повторяет чтение и формирует полный XLSX; она может отличаться
от предыдущего просмотра, если между запросами изменили карточки.

Сравнение выполняется в одной read-only SERIALIZABLE транзакции и учитывает все
54 поля и кратность дубликатов. Расхождение запрещает общую выгрузку: скачайте
результаты каждого запроса отдельно. Пустая выборка допустима; количество строк
видно в интерфейсе и на листе Report. Артикул, отсутствующий в результате, мог
быть исключён условиями складов/наценок, а не отсутствовать в справочнике.

Оба исходных запроса имеют по 54 позиции. Первые две теперь содержат текущий
артикул: разные локальные таблицы Access заменены одним введённым списком без
переименований. Позиции 55–57 Excel относятся к сборкам и отсутствуют в запросах.
Складские ID и наценки сохранены из legacy-контракта. Выборка через view использует
`card_tov`, не `card_tov_export`. Вторая наценка — `RUB_PRICE`.

Вся ФОЛИО-операция — SELECT: без DDL, создания/изменения товаров, изменения цен,
резервов, счётчиков, фоновых задач и запуска макросов. Чтение может держать shared
locks до 60 секунд. Лимиты: 500 запрошенных артикулов, 50 000 строк результата;
превышение лимита завершает запрос ошибкой без частичного файла.

Используются существующие Java URL/API token из настроек синхронизации цен и
LAVKA_TOKEN backend. Сначала выпускается Java, потом WordPress-код. При ошибке
проверить сервис, токен, Paint_Ua и лимит; повтор чтения допустим. Сообщения не
раскрывают SQL/реквизиты подключения. XLSX скачивается через nonce/capability,
временные файлы удаляются, публичная копия не сохраняется. Откат только кодовый.
Учётные цены и прибыль пока остаются в прежних меню.

Проверки: PHP selection/transport/XLSX, Java DAO/controller unit tests,
desktop/mobile с синтетическими ответами. Live-сверка текущего view и таблиц
фиксируется отдельно: наличие двух одинаково устроенных запросов ещё не доказывает
равенство результатов в работающей базе.

Живая проверка 2026-10-18 с настройками подключения Java: логин и пользователь
базы buh, Paint_Ua. Оба SELECT вернули 36 798 строк, все 54 поля и кратность
строк совпали. Предыдущий отказ чтения card_tov больше не воспроизводится.
Проверка выполнялась через JDBC, не через опубликованный HTTP endpoint.

## Выбор из Excel и выгрузка по шаблону

В режиме «Артикулы из списка» вставьте одну колонку артикулов или загрузите XLS/XLSX
до 5 МБ. Укажите букву колонки (A по умолчанию) и первую строку данных (2, чтобы
пропустить заголовок; для списка без заголовка выберите 1). Читается первый лист.
«Загрузить список» заменяет поле ввода; проверьте список, затем нажмите чтение или
выгрузку. При ошибке прежний список сохраняется. Пустая выборка ввода отклоняется;
для всей базы явно выберите «Все доступные карточки».

Повторы удаляются, лимит — 500 уникальных артикулов. Текстовые начальные нули и
числовая маска нулей сохраняются. Уже потерянные в исходном Excel цифры восстановить
нельзя: храните артикулы как текст. Формулы и ячейки ошибок в выбранной колонке
отклоняются; макросы не исполняются. Импорт читает только список, без обращения
к ФОЛИО. Файл остаётся временной PHP-загрузкой и удаляется по окончании запроса.

XLSX содержит лист «НК» со всеми 57 заголовками исходного шаблона в том же порядке.
Первые 54 колонки заполнены данными запроса; последние три колонки сборок пусты.
Это формат XLSX с сохранённой структурой, не побайтовая копия старого XLS и его
оформления. Лист Report содержит результат проверки и не найденные артикулы.
Импорт зависит от общего PhpSpreadsheet из wp-content/vendor (штатный MU-autoload).
Без этой библиотеки вставка списка и выгрузка продолжают работать.

Проверки: реальные синтетические XLS/XLSX, кириллица, начальные нули, выбор колонки,
повторы, пустой список, формулы, лимит 500 и capability/nonce. Deployment: обновление
lavka-price-sync после Java endpoint; production в этой задаче не изменялся.
