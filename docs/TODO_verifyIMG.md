## Реализованный рекомендуемый полный цикл

После обязательной проверки оператор отдельным подтверждением запускает полный цикл:

1. Плагин берёт только строки без блокирующих ошибок.
2. Для неправильного исходного имени создаётся серверная копия с каноническим именем;
   исходный файл на компьютере пользователя не переименовывается.
3. Копия загружается через штатный WordPress Media Library pipeline. Media Cloud
   отправляет оригинал и созданные WordPress миниатюры в OVH/S3. Для этого вызова
   отключается только автоматическая замена большого оригинала на `-scaled`: исходное
   каноническое имя сохраняется, а обычные зарегистрированные миниатюры создаются.
4. Вложение проверяется, но ещё не назначается товару WooCommerce.
5. Под глобальным Lavka lock обновляется Java-индекс OVH/S3. Если загруженный объект ещё
   не появился, после короткой паузы выполняется только одна ограниченная повторная
   индексация для ожидающих строк.
6. Из `s3_media_index` повторно читается точное доказательство объекта: имя, полный
   ключ, размер и ETag.
7. Для каждого SKU читаются текущие ссылки ФОЛІО и строится точная операция
   `set_main`, `update_gallery` или `add_gallery`.
8. Java обязательно получает preview, затем тот же запрос применяется с тем же
   `externalRequestId`.
9. Только после `applied`/`noop` изображение назначается товару WooCommerce и attachment
   связывается с товаром.
10. Формируется CSV-отчёт и событие в общем журнале Lavka.

Если этап после загрузки не завершился, вложение сохраняется как частичное. Повторная
проверка тех же файлов продолжает обработку существующего attachment и не создаёт
автоматический дубликат `-1`. Выбор папки в браузере служит только способом выбрать
файлы и не даёт сайту права менять исходную папку пользователя. Если API глобальной
блокировки Lavka недоступен, проверка остаётся доступной, но запись останавливается до
создания attachment.
