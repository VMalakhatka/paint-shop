# Тестовый доступ к WayForPay

В режиме ограниченного доступа способ оплаты картой скрыт от гостей и обычных клиентов. Сам шлюз остаётся включённым в WooCommerce. Этот allowlist ограничивает видимость способа оплаты, **но не переключает merchant в sandbox** и не доказывает, что деньги тестовые.

## Оплата → чек Checkbox

Проверено: 2026-10-16, повторный read-only production-аудит после выпуска 0.1.1:
для одной новой live-оплаты подтверждены очередь `SUCCEEDED`, чек `DONE`,
транзакция Checkbox `DONE` / `response_status=OK` и созданный счёт ФОЛИО с `WFP`.
Это не подтверждает все ветки приёмки: получение email клиентом и полный
браузерный возврат отдельно не проверены. Старую возвращённую оплату не повторять.
Владелец сценария — отдельный `pc-wayforpay-checkbox`, исполнитель —
`pc-checkbox-fiscalization`. Только проверенный Approved callback запускает очередь;
статус заказа или браузерный redirect недостаточны.

Настройки, развёртывание двух плагинов, проверка налогов/режимов, приёмка,
пауза и откат: [канонический runbook адаптера](../wp-content/plugins/pc-wayforpay-checkbox/README.md).
Автоматические возвраты не включены: подтверждённый refund требует построчного разбора.
Не открывать WayForPay всем клиентам до внешнего сквозного теста.

До оплаты можно открыть настройки Checkbox → **Preview shift opening**, проверить
кассу/кассира/test-live и отдельно подтвердить открытие. В live это фискальная
операция. Порядок и stopping conditions: [Checkbox runbook](../wp-content/plugins/pc-checkbox-fiscalization/README.md#manual-shift-opening-and-diagnostics-011).
Для оплаченного заказа используйте сверку/возобновление в его карточке; не создавайте
новый заказ и не оплачивайте повторно ради чека.

Ручной чек по продаже только из ФОЛИО пока **не реализован**: контракт команды есть,
но готового Java endpoint и UI подтверждения нет. `linkedPayments` API документов
даёт исходные данные, не разрешение на чек. Владелец 2026-10-16 выбрал только
проведённый и привязанный платёж ФОЛИО (не ручную отметку кассира). Требуются
серверная проверка суммы/типа платежа, поиск выданного чека (включая другие кассы),
preview/apply и связь Woo → ФОЛИО → чек. Для Woo-продажи восстанавливается исходная
WayForPay-операция, а не создаётся вторая с ключом ФОЛИО.

## Банковская оплата в ФОЛИО — согласовано, ещё не реализовано

Владелец подтвердил 2026-10-16: все поступления WayForPay по ФОП Малахатка
учитываются на складе **5**, даже если счёт/товар относится к другому складу.
Название склада «Одесса» не отменяет это правило централизованного учёта денег.
Платёж должен быть связан с созданным из заказа счётом; плательщик берётся из
этого счёта, а не из текущей привязки профиля на момент повтора.

Новый customer без персональной привязки получает штатного «Интернет клиента»;
существующую привязку менеджера не заменять. Переназначение профиля влияет на
будущие документы, но не должно переносить уже созданные счета/платежи.

Сейчас `WFP` в счёте — информационная отметка, **не запись банковского прихода**.
Новые настройки production для этой функции пока не добавлять: consumer/API ещё
не реализованы. Точный план, проверка native payment workflow, защита от дублей
и критерии допуска: [задание на банковские оплаты](api/FOLIO_WFP_PAYMENT_BACKEND_TASK.md).
Развёртывание, первая запись и обработка старых оплат требуют отдельных решений.

## Добавить тестового пользователя

1. Открыть **Пользователи** и перейти в профиль нужного клиента.
2. В разделе **Тестовий доступ до WayForPay** включить **Показувати WayForPay цьому користувачу в обмеженому режимі**.
3. Сохранить профиль.
4. Пользователь должен войти в свой кабинет до перехода на страницу оформления заказа.

В режиме ограниченного доступа WayForPay не показывается гостям, даже если их email совпадает с email тестового пользователя.

## Открыть WayForPay всем клиентам

1. Открыть **Лавка → Лавка: налаштування → Лавка: тестовий доступ WayForPay**.
2. Выбрать **Усі клієнти**.
3. Нажать **Зберегти режим доступу**.

После переключения отдельные отметки в профилях пользователей можно оставить: в общем режиме они не ограничивают оплату и пригодятся, если тестовый режим понадобится вернуть.

## Проверка

- гость не видит WayForPay в ограниченном режиме;
- авторизованный пользователь без отметки не видит WayForPay;
- отмеченный авторизованный пользователь видит WayForPay;
- в режиме для всех WayForPay видят все клиенты, если шлюз включён и доступен по правилам самого платёжного плагина.

Код: `wp-content/mu-plugins/pc-wayforpay-test-access.php`.
