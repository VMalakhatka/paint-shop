# Меню категорий: локальная проверка

Проверено: **2026-09-15**, только `paint.local`. Реализация: `paint-shop-ux`.
Production, Java, серверные настройки и бизнес-данные не изменялись.
На момент проверки коммит, push и deploy не выполнялись. Локальный сайт запущен
владельцем. 2026-09-16 владелец подтвердил локальную работу и разрешил commit/push;
production deploy остаётся отдельным шагом.

## Что проверено

Настоящий локальный renderer: `WPB_Accordion_Menu_Widget::widget()` →
`wpb_wmca_accordion_pro` → `templates/taxonomy.php` → WPB category walker.
В `sidebar-1` находятся block widget и WPB category widget. Настройки последнего:
product_cat, name ASC, hide_empty=on, show_count=off, hide_out_of_stock=off.
Подмена сделана до walker, не путём удаления уже готового HTML. Другой block widget
не заменяется. [Контракт и кэш](../wp-content/plugins/paint-shop-ux/README.md).

Локальная база отличается от production: старое меню здесь содержит **1 776**
ссылок, а не 3 278 из отдельного production-аудита от 2026-09-14
(`docs/SITE_PERFORMANCE_AUDIT_2026-09-14.md`, не входит в коммит меню).
Числа из двух окружений не смешиваются. В частности, production 4,7393 с относилось
к полной sidebar через CLI, а не к обычному HTTP или таймеру одного widget.

## Серверный renderer

Отдельный воспроизводимый A/B CLI-профиль на PHP **8.3.23**, без persistent object
cache. В одном процессе, по семь последовательных вызовов каждого варианта,
та же категория и настройки. Для нового widget и отдельно для branch создан
свежий namespace кэша меню; первый вызов холодный именно относительно этого кэша.
Общие term caches WordPress не очищались. Sidebar замеряется отдельным блоком
после widget-вызовов, поэтому её серия тёплая. Это **не HTTP TTFB**.

| Измерение | Первый вызов, с | Последующие 6, с | SQL первого / остальных | Размер, байт |

Количество SQL включает чтение/запись transients и прогрев. Холодное новое меню
делает больше запросов, но строит только нужные строки; тёплый renderer использует
кэш. Cold index читает ID/parent/count всей taxonomy один раз, не полные имена,
ссылки или дерево HTML; эта стоимость не скрывается за утверждением «всегда O(1)».

## Функциональные проверки

- Полный read-only обход: **564 страницы веток**, максимум 30 строк за ответ.
  Все **1 776** term ID совпали с прежней WordPress hierarchical/hide_empty выборкой.
  Нет дубликатов; каждый результат принадлежит непосредственному родителю;
  все ссылки совпадают с get_term_link.
- Пустой лист, конец выдачи, отсутствующий родитель, неверный offset/locale;
  правильные 200/400/404. Синтетические 40 уровней и цикл завершаются корректно.
- Desktop **1440×1000**, mobile **390×1000**: текущая ветка развернута,
  aria-current и aria-expanded верны; семь уровней, переполнений текста нет.
- Быстрые открыть/закрыть/открыть дают ровно один GET. Повторное раскрытие
  загруженной ветки не запрашивает её снова. «Ще категорії» без повторов ID.
  Активная категория за первой порцией остаётся видимой и после подгрузки
  возвращается на своё место в сортировке; проверено сравнением ID с двумя API-порциями.
- Имитация 503 только в браузере: видимая ошибка, успешный ручной retry.
  Клавиатура Enter и обычные ссылки работают. При выключенном JS не остаются
  мёртвые кнопки: переход ведёт на категорию с плитками дочерних разделов.
- Кабинет и пустая корзина дают одну ссылку в каталог без menu JS; пустой checkout
  штатно перенаправляет в корзину. Ветка is_checkout покрыта кодом, но непустой
  checkout отдельно не прогонялся: заказы и содержимое корзины не менялись.
- UA проверен на реальных страницах. RU: реальный PHP renderer со switch_to_locale
  создаёт тестовую разметку вне webroot; её подставляет браузер на локальной странице,
  JS и GET веток работают с locale=ru_RU. Настройка языка сайта не менялась.
  Названия самих категорий общие, отдельной многоязычной taxonomy нет.
- Namespace кэша меняется после term invalidation. В lavka-total-sync после SQL
  recount уже есть clean_term_cache: проверено по helpers.php, синхронизация для
  теста не запускалась. Никакого Java apply.
- Существующий catalog-filters integration smoke: **12 PASS**, включая категорию,
  поставщика, SKU-поиск, ограничения выдачи и стабильную пагинацию.
- PHP lint, JS syntax check, MO compilation, git diff --check и documentation
  validation. Браузерных ошибок в проверяемых UI-сценариях нет. Существующее
  предупреждение раннего textdomain EmailKit в CLI не относится к меню.

## Границы и публикация

Реализован только пункт 1 аудита. Gzip, автоматический reload каталога, SLW cache
versions, ресурсы импорта и прочие пункты не изменялись. Старый accordion CSS
консервативно оставлен; JS удаляется лишь при отсутствии реально использованных
WPB shortcodes и чужих зависимостей. На мобильном сохранено положение sidebar
ниже основного контента, а не введено новое мобильное меню.

Это локальные результаты, не обещание production TTFB. На production остаётся
проверить настройки виджета, размеры его веток, активные сторонние shortcodes,
реальные роли и каталог. Особенно широкие/глубокие структуры сохраняют ссылку
на активную ветку даже сверх обычного лимита; локальная структура в лимитах.
Polylang/WPML не проверены: их сейчас нет в активном локальном окружении.

Каноническая оптовая инструкция, код «Як замовляти», UA/RU и снимок меню обновлены
локально. Production-справка **не опубликована** и не проверена под оптовой ролью.
Откат: убрать require category-menu.php из Paint Shop UX; прежние настройки WPB
сохранены и старое меню вернётся. Никаких миграций/переноса БД не требуется.

Название коммита: `perf: lazy-load catalog category branches`.

## Собственный виджет: 2026-09-17

Локальное продолжение: Paint Shop UX **1.3.0**, виджет **«Категорії Лавки»**
(`psu_category_menu`). Production, Java, товары и заказы не изменялись.
Это отдельная доработка после коммита `a813705`. После локальной проверки владелец
подтвердил работу и разрешил commit/push. Production deploy и перенос его виджетов
выполняются отдельно по инструкции владельца компонента.

### Зависимости WPB

Проверены активные sidebars, сохранённые widget options, содержимое страниц/блоков,
шаблоны и post metadata (включая Elementor), ссылки из options и собственный PHP/JS.
Поиск охватывал три shortcode плагина и его block/Elementor names из исходного кода.
Единственное активное использование локально: WPB category widget в основной sidebar.
Других используемых shortcodes/блоков не найдено. Оставшиеся ссылки в options
относятся к регистрации plugin/лицензии, сохранённым настройкам другой темы и
старому custom CSS; их не удаляли. На production этот аудит нужно повторить.

### Результат

- Настройки меню скопированы в собственный widget option: прежний заголовок,
  сортировка name ASC, hide_empty=true, show_count=false.
- Место в sidebar сохранено, соседний block widget не менялся.
- Старый экземпляр и WPB settings не удалены; резервная копия хранится до переноса.
- Перенос выполняется только явно через **Вигляд → Категорії Лавки**. Открытие
  витрины не меняет sidebar. Админка защищена capability и nonce; POST без nonce
  вернул HTTP 403. После успешного POST выполняется redirect, обновление страницы
  не повторяет операцию.
- WPB отключён **только локально**. Новое меню и REST работают без него;
  на проверенных страницах нет его CSS/JS. Для WPB, ещё не перенесённых в другом
  окружении, оставлен прежний адаптер. Автоматической деактивации WPB в коде нет.

### Проверки

- **24** локальные проверки настроек и миграции: права, устаревший план, lock,
  сохранение соседних виджетов, существующие native IDs, повторный запуск,
  конфликт отката, прерванная запись и отказ записи sidebar. Исходные options
  каждого теста восстанавливаются в finally.
- Реальный цикл: перенос через браузер → редактор виджетов → отключение WPB →
  повторное открытие редактора → включение WPB и успешный откат → повторный перенос
  и окончательное отключение WPB. Учтена штатная очистка неактивного WPB экземпляра
  редактором; остальные изменения sidebar не игнорируются при откате.
- В штатном блочном редакторе WordPress проверены название, поля и сохранённые
  значения собственного виджета до и после отключения WPB.
- Без WPB полный обход вновь дал **1 776 категорий**, **564 страницы веток**,
  максимум 30 строк за ответ и семь уровней. Без пропусков и дубликатов.
- Browser smoke: 1440×1000 и 390×1000, активная/глубокая ветка, повторные клики,
  пагинация ветки, 503 и retry, no-JS, компактный кабинет/пустая корзина, UA/RU,
  ошибки REST и отсутствие WPB assets. Ошибок JavaScript и переполнений меню нет.
- RU использует временную отрисовку PHP, язык сайта не переключался. Временная
  локальная административная сессия для теста удалена вместе с файлом cookies.
- PHP lint, JS syntax check, компиляция переводов, diff check и documentation check.
  Существующее CLI-предупреждение EmailKit не относится к этому изменению.
