# Операции менеджера: карточки и сборка ФОЛИО

Проверено: 04.11.2026, локальный код, тесты и интерфейс с искусственными ответами.
Публикация ожидает deploy Java и WordPress. Живая база в этой задаче не изменялась.

Постоянное решение владельца от **23.10.2026**: российская база `Paint_Rus` больше
не поддерживается. Все действия макросов для неё пропускаются сейчас и в будущих
переносах; повторно применять их к `Paint_Ua` нельзя. Текущая реализация уже
ограничена Paint_Ua. Исторические RUS-запросы остаются в каталоге для справки.

## Как пользоваться

С 24.10.2026 разделены два пункта меню **Лавка ФОЛИО**: **Операции менеджера**
для пяти операций карточек/выборки и **Збірка накладна — розрахунок**
(`lps-folio-assembly`) для сборки. Сборки больше нет в списке операций карточек.
Каждый экран показывает только свою часть истории; сохранённые задания и выгрузки
остаются доступны. На экране сборки доступны расчёт и экспорт, без кнопки записи
карточек. Создание накладных ФОЛИО планируется здесь позже и пока не реализовано.

Доступ нужен тот же, что для
валютных цен (`manage_lavka_prices`). Все операции ограничены **Paint_Ua**.

1. Выберите операцию. Подготовьте колонки в порядке, который показан на экране.
2. Загрузите XLS/XLSX/CSV **либо** вставьте ячейки из Excel в текстовое поле.
   Шапка необязательна. Читается первый лист, максимум 500 строк и 5 МБ.
   CSV должен быть UTF-8; при десятичных запятых используйте `;` или табуляцию.
   Формулы Excel не принимаются: вставляйте их значения. Артикулы храните текстом,
   особенно если важны начальные нули. Остальные листы не загружаются.
3. Нажмите **Предпросмотр / рассчитать**. Проверьте старые/новые значения,
   все склады, отсутствующие артикулы и очистку полей. Скачайте Excel предпросмотра.
4. Для изменения карточек отметьте подтверждение и нажмите **Применить в ФОЛИО**.
   Успех — статус «Сохранено и проверено в ФОЛИО». Для выборки и расчёта сборки
   применение не требуется: скачайте результат.

Пустая ячейка в обновляемом поле означает **очистить до NULL**, а не «оставить старое».
Удаляются пробелы по краям текста. Для групп нужны все шесть колонок: пропущенные
колонки отклоняются, пустые значения очищают соответствующие группы.
Повторные артикулы для обновлений отклоняются. Имя до 200 символов, группа до 30,
единица до 10, описание до 5000, артикул до 20; символы должны представляться в CP1251.

## Что делает каждая операция

| Операция | Колонки | Результат |
|---|---|---|
| Наименование товара | COD_ARTIC, NAME_ARTIC | Обновляет имя на всех складах, где уже есть карточка |
| Группы товара | CODE_ARTIC, NGROUP_TVR, NGROUP_TV2, NGROUP_TV3, NGROUP_TV4, NGROUP_TV5, NGROUP_TV6 | Обновляет все шесть групп на всех складах |
| Единица измерения | COD_ARTIC, EDIN_IZMER | Обновляет единицу на всех складах |
| Описание товара | COD_ARTIC, DESCRIPTION | Добавляет отсутствующие записи общего справочника, затем обновляет описания; складские карточки не создаёт |
| Артикулы по главному артикулу | ARTIC_BAZA | Выдаёт ARTIC и ARTIC_BAZA; повторные входные строки сохраняются, отсутствие совпадения даёт NULL/NULL |
| Сборка накладная — расчёт | Полный технический вход ниже | Три результата исходного макроса и рассчитанный вход; накладную в ФОЛИО не создаёт |

Для первых трёх операций артикулы без карточек не создаются — они показаны в списке
отсутствующих. Для описаний этот список означает **будут добавлены новые строки ALL_ARTC**.

## Сборка и мультисборка: инструкция менеджера

Источник процесса: инструкция менеджера, переданная владельцем 04.11.2026,
и макрос «Сборка накладная» в `Салимон_Запросы_из_Фолио.mdb`.

1. Откройте **Лавка ФОЛИО → Збірка накладна — розрахунок**.
2. Выберите режим и подготовьте **две колонки** в указанном порядке:

   | Режим | Артикул | Количество |
   |---|---|---|
   | Сборка: по артикулам родителей | ARTIC_roditel | KOL_rod_razob |
   | Мультисборка: по артикулам детей | ARTIC_rebenok | kol_reb_pol |

   Для обычной сборки укажите количество списываемого родителя; для мультисборки —
   количество получаемого ребёнка. Количества положительные, родитель допускает
   дробь, ребёнок — целое число от 1 до 32767 (тип Integer исходной таблицы).
   Пустые артикулы/количества отклоняются. Можно вставить ячейки или загрузить
   XLS/XLSX/CSV, с шапкой либо без неё. Правила файлов описаны выше.
3. Нажмите **Розрахувати збірку**. Каждый запуск использует свежую входную таблицу:
   удалять строки предыдущего расчёта, как в Access, не нужно. При смене режима
   введённые ячейки и выбранный файл очищаются, чтобы не перепутать родителей и детей.
4. Проверьте итоговую таблицу **ARTIC / KOL_R / PRICE**. Отрицательные количества —
   списание, положительные — приход. Кнопка **Скопіювати для IMPORT DBF** копирует
   значения без шапки, через табуляцию, для вставки в прежнюю таблицу `IMPORT DBF`.
   Альтернатива — **Завантажити Excel**, первый лист **IMPORT_DBF**, колонки A:C
   начиная со второй строки. Повторяющиеся строки не объединяются.
5. Далее используйте прежний процесс: подготовьте DBF через `IMPORT DBF`, откройте
   накладную сборки в ФОЛИО и загрузите DBF. Сайт сейчас рассчитывает строки, но сам
   не создаёт DBF-файл или накладную ФОЛИО.

**Детали расчёта.** Для проверки сохранены исходные результаты **ASSEMBLY_18**,
**ASSEMBLY_9**, **ASSEMBLY_91** и рассчитанные поля **ASSEMBLY_INPUT**. Итоговый
IMPORT_DBF — их первые три колонки в порядке 18 → 9 → 91; ASSEMBLY_INPUT туда не входит.
Числа, знаки и повторяющиеся строки сохраняются без дополнительного расчёта,
группировки или округления. Это единая выгрузка результатов трёх SELECT макроса.
Если результат пуст либо содержит пустой артикул, отсутствующее/нечисловое количество
или цену, кнопка копирования и лист IMPORT_DBF недоступны; Excel сохраняет
диагностические таблицы и отметку ASSEMBLY_INCOMPLETE. Проверьте состав и цены склада 7.

**Начальные значения.** MDB проверен read-only через `mdb-prop`: новая строка
`для сборки` имеет NULL для второго, не введённого артикула и 0 для остальных
числовых полей, включая SLOG и CENA_REB. Сайт добавляет именно эти значения к двум
колонкам. SLOG не устанавливается в 1 по выбранному режиму: это делает шаг 13
по наличию ребёнка в ALL_RAZBORKA_SLOJ. Для родительского ввода шаг 12 находит ребёнка,
количество и цену. Для детского ввода количество ребёнка сохраняется, шаг 4
разворачивает компоненты. Шаг 2 не применяется к строке с пустым родителем.

Расчёт Java и его шесть входных полей не менялись. **Полная таблица Access
(расширенный режим)** сохраняет прежний технический ввод всех шести колонок;
там SLOG задаётся явно и пустые числовые ячейки остаются NULL. История сохраняет
режим; старые задания открываются как полный формат без потери данных.
Подтверждённая владельцем цена готового товара — сумма стоимости всех списанных
компонентов, делённая на полученное количество. Исходные цена/курс берутся со склада 7.
Неоднозначные связи и повторные получаемые артикулы сложной сборки останавливают расчёт.

Локально проверены обе схемы ввода, начальные значения, XLS/XLSX/CSV/вставка,
проекция результата, история, ошибки и интерфейс на искусственных ответах.
**Численная сверка с реальным результатом Access ещё нужна:** один исходный пример
родительской сборки и один пример мультисборки с результатами ARTIC/KOL_R/PRICE
при тех же рецептах и ценах. Без такой сверки нельзя заявлять полное совпадение
денежной арифметики Jet и SQL Server 2000. Живые данные ФОЛИО не изменялись.

## История, ошибки и восстановление

«Последние операции» показывает 50 последних запусков текущего пользователя.
История сохраняет исходные данные, снимок до/после, автора, файл и SHA-256.
Выгрузка Excel содержит Input, Changes, Saved, результаты чтения и Report.
Коды и текст записываются как текстовые ячейки, поэтому начальные нули сохраняются,
а текст вида `=...` не исполняется как формула. Цены/количества в выгрузке тоже текстовые:
при самостоятельных формулах Excel преобразуйте их в числа осознанно.

Предпросмотр для записи действует 15 минут. Если данные изменились, запись не
выполняется: создайте новый предпросмотр. Если другой процесс занимает общий lock,
дождитесь его завершения и повторите неподтверждённую операцию.

При **неизвестном результате** не применяйте тот же файл заново. Нажмите «Проверить
статус», в том числе после повторного входа через историю. Если статус не восстановился,
администратор должен сравнить ФОЛИО с сохранённым снимком. Перезапуск Java уничтожает
токены в памяти, но не журнал WordPress; старый токен не даёт разрешения на повтор.
Автоматического отката завершённой записи нет: обратные значения сначала надо сверить
с текущими данными, чтобы не затереть чужие последующие правки.

## Владение и установка

WordPress: `lavka-price-sync/inc/folio-manager*.php`, `assets/folio-manager.js`,
домен переводов `lps-manager` (RU/UK). Контекстная справка находится на том же экране.
PHP проверяет capability, nonce, принадлежность задания пользователю и одноразовую
отправку, хранит журнал `lps_manager_job_*`, `lps_manager_claim_*`,
`lps_manager_history_<user>` в non-autoload options. Автоматического удаления аудита
нет; в меню видны последние 50, прежние записи сохраняются для восстановления.

Java владеет SQL, типами, транзакцией и проверкой результата:
`/admin/folio/manager/preview|apply|status`, существующий X-Auth-Token.
Точный контракт и ограничения — `docs/api/FOLIO_MANAGER_OPERATIONS.md` Java-репозитория.
WordPress не обращается к MSSQL напрямую. Для записи используются существующие общий
ecosystem lock и MSSQL mutex перерасчёта. При UNKNOWN WordPress удерживает lock до
истечения 10 минут и не повторяет команду автоматически.

Новый плагин/миграция/секрет не нужны. Требуются сборка и согласованный deploy обоих
компонентов. До деплоя проверить auth/недоступный Java/preview на контрольных данных,
наличие defaults и текущую схему ФОЛИО. Производственный deploy и фактическое применение
данных — отдельные действия; в этой задаче они не выполнялись.

Перенос сборки в отдельное меню от 24.10.2026 меняет только WordPress UI.
Java API, расчёт, входной формат и граница Paint_Ua сохранены. Для этого переноса
не нужна новая сборка Java; публикация изменения меню ожидает WordPress deploy.

Адаптация ввода по инструкции менеджера от 04.11.2026 выполнена в WordPress.
Новая сборка Java для неё не требуется при наличии ранее реализованного
`/admin/folio/manager/preview`. Публикация интерфейса ожидает согласованный deploy.
