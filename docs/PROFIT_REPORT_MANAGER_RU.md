# Отчёт прибыли: инструкция для менеджера

**Короткая инструкция для передачи менеджеру:** войдите в кабинет управления сайтом → **Lavka → Отчёты → Лавка: прибыль ФОЛІО**. Если что-то непонятно, раскройте **«Инструкция для менеджера»** над выбором периода. Там описаны запуск, параметры и скачивание Excel.

[Прямая ссылка на отчёт](https://kreul.com.ua/wp-admin/admin.php?page=lavka-profit-report). В украинском интерфейсе инструкция называется **«Інструкція для менеджера»**.

Оформленная инструкция встроена в страницу и доступна без запуска расчёта, в том числе при ошибке загрузки данных. Ниже — её подробная текстовая версия.

1. **Выберите месяц.** В полях «С месяца» и «По месяц включительно» поставьте одинаковый месяц. Для нескольких месяцев укажите начало и конец периода.
2. **Если отчёт уже готов:** нажмите «Показать сохранённые отчёты», затем «Открыть сохранённый месяц». Пересчитывать его не нужно.
3. Для нового расчёта раскройте ручные параметры. Проверьте доплату Одессы и курс RUB, если есть зарплата в рублях. Пустая доплата Одессы означает 5000 грн; **0** отменяет её. Киев — не заполнять, 0. Число работников указывать не нужно.
4. Нажмите **«Рассчитать и сохранить выбранные месяцы»** и дождитесь завершения. При выборе нескольких месяцев параметры применятся к каждому из них. Если доплаты менялись, рассчитывайте эти месяцы по одному.
5. Проверьте месяц, прибыль и предупреждения. **Прочерк означает отсутствие данных, а не ноль.** Если отчёт требует проверки, передайте ответственному Excel и текст предупреждения. После ошибки соединения сначала откройте сохранённые отчёты: результат мог уже сохраниться.
6. Нажмите **«Экспорт отчёта в Excel»** для открытого месяца или **«Сохранённый период в Excel»** для периода. Файл обычно попадёт в папку «Загрузки».

При просмотре периода складываются сохранённые суммы выбранных месяцев, даже
если в них использовались разные склады. Остатки показываются на начало первого
и конец последнего месяца. Это правило согласовано 24.10.2026 и применяется после
обновления Java: достаточно нажать «Показать сохранённые отчёты», пересчитывать
месяцы не нужно. Если самой суммы или месяца нет, итог остаётся прочерком.

## Склады и исключения из остатков

На странице прибыли раскройте **«Склады и исключения из остатков»**
(украинский интерфейс — **«Склади та виключення із запасів»**).

1. Выберите склады **продаж** отдельно для Киева и Одессы: они определяют
   базовую валовую прибыль города.
2. Выберите склады **остатков** отдельно для каждого города. В каждом списке
   нужен хотя бы один склад. Между городами склады одного вида расчёта
   пересекаться не должны; совпадение складов продаж и остатков допустимо.
3. Отметьте группы или подгруппы, которые надо **исключить из остатков**.
   Эти исключения общие для обоих городов. Выбранная ветка исключается вместе
   со всеми дочерними подгруппами. Полный путь помогает различать одинаковые
   названия в разных ветках. Поиск не снимает ранее поставленные отметки.
4. Нажмите **«Сохранить склады и исключения»**, затем рассчитайте нужные месяцы.

Пустые списки исключений означают отсутствие дополнительных исключений.
Исключения групп не меняют прибыль от продаж, МК, расходы и налоги. МК остаются
на складах 1 (Киев) и 5 (Одесса); отборы расходов остаются отдельными для каждой
статьи. Группа товара определяется по текущей карточке ФОЛИО на момент расчёта,
а не по историческому названию группы в выбранном месяце.

Сохранение настроек не пересчитывает месяцы. Старые отчёты и их Excel сохраняют
свои суммы; у новых отчётов в «Применённых параметрах» и Excel записаны версия
настроек, склады и полные пути исключений. Для старых отчётов без такого снимка
это явно указано — текущие настройки к ним не подставляются.

Если другой менеджер изменил настройки или сохранение не подтвердилось,
нажмите **«Загрузить сохранённые настройки»**, проверьте выбор и только потом
повторите сохранение. При расчёте нескольких месяцев используется одна версия
настроек; при конфликте серия останавливается, уже сохранённые месяцы остаются.
Нужны Java с API настроек и миграцией V20 и Lavka Reports 0.12.0; до их деплоя
новый редактор не подтверждает наличие функции на рабочем сайте.

## Фирмы для налогов

Над выбором периода раскройте **«Фирмы для налогов: розница и опт»**.
В двух таблицах можно добавлять, редактировать и удалять коды фирм ФОЛИО.
Начальные списки: розница — **МИХНФОП, МАЛАФОП**, опт — **КУЗНФОП, КОНДФОП**.
Оставляйте в списках и прежние, и действующие фирмы: даты работы задавать не нужно.
Отчёт сам отбирает налоговые документы выбранного месяца по общему правилу периода.
Одна фирма не может входить в оба списка.

Нажмите **«Сохранить списки фирм»**, затем выполните новый расчёт нужных месяцев.
Сохранение настроек не меняет старые отчёты. Их использованные списки и версия
показаны в параметрах самого отчёта и в Excel. Если другой менеджер уже изменил
списки или сохранение не подтверждено, загрузите сохранённые списки, проверьте их
и только затем повторите свои изменения.

**Нераспределённые налоги** нельзя считать нулём: там собраны суммы и документы
фирм, для которых направление не определено. Проверьте фирму, добавьте её в нужный
список и пересчитайте месяц. До этого прибыль по городам требует проверки.

## Что будет в Excel

Начните с листов **Киев** и **Одесса**. Колонки расположены как в рабочем шаблоне:

**A–G: № · Статья · Краткое имя · Тип операции · Код назначения · Расход: склады · Банк: склады. H: Ручной ввод, грн. I: Отчёт, грн.**

В **H** вносите свои суммы только в пустые ячейки: шесть итоговых формул на каждом листе уже стоят на своих местах. Не заменяйте их данными сайта. В **I** находится результат Java, включая его официальные итоги; ручные формулы H его не меняют. На сайте в H показывается текст формул, редактируется ручной шаблон в Excel.

Порядок строк соответствует шаблону «Прибыль_с_октябрь_2025.xls» от 07.10.2026: Киев — строки 4–38, Одесса — 4–31, включая пустые разделители. На сайте нажмите **«Копировать данные сайта для Excel»** у нужного города и вставьте значения в **I4**, либо в новую колонку сравнения начиная с 4-й строки. Пустые строки сохраняются, поэтому суммы не съедут. **В H весь столбец не вставляйте.** При запрете буфера обмена появится выделенное текстовое поле — скопируйте его вручную.

Вводите валовую прибыль в пять строк категорий: магазины, партнёры, дилеры, покупатели и художественные салоны. **Базовая валовая прибыль теперь считается автоматически как сумма этих пяти строк**; повторно вводить её не нужно. Затем формула один раз добавляет чистый вклад МК и вычитает операционные расходы.

На Киеве: H30 = SUM(H31:H35), H36 = H30+H28, H38 = H36−H37. На Одессе: H23 = SUM(H24:H28), H29 = H23+H21, H31 = H29−H30. Базовый итог выделен как подытог над расшифровкой, отдельная строка «Итоги прибыли» удалена.

Суммы сайта в I остаются результатом Java. Он учитывает часть прибыли МК, уже вошедшую в базу ФОЛИО, поэтому ручная формула «база + чистый вклад МК» может отличаться. Отборы статей, расчёт Java и сохранённые ревизии этой правкой не изменены.

Дополнительные работы находятся после зарплат. Банк, налоги и нерегулярные расходы Киева — после телефона, затем аренда и телефон опта. Хозяйственные услуги и расходы Киева показаны одной строкой сразу после дополнительных работ; прежняя дублирующая строка удалена. Согласованный отбор: НЕРЕГУЛ, операции РАСХОДЫ КИЕВОПТ и РАСХОДЫ КИЕВА, касса и банк всех складов, любой код назначения. Уточнение владельца от 15.10.2026: для нерегулярных расходов Киева НЕРЕГДОН учитываются касса и банк всех складов, без ограничения операции и назначения. Это заменяет прежнее правило «только банк». Реализация нового отбора передана Java; её готовность и production-деплой проверяются отдельно. Эти изменения отбора требуют нового расчёта после обновления Java. Отборы всегда берутся из той версии Java, которая сформировала отчёт.

После основных расходов Киева идёт опт: аренда и телефон. Импортный транспорт расположен **ниже общих расходов** и не вычитается повторно. Мастер-классы показаны для обоих городов тремя строками: доход, возвраты и чистый вклад. Технические суммы «МК уже в базе» и «Корректировка МК» скрыты в основной таблице; Java по-прежнему учитывает их, чтобы не добавить МК дважды. Итоги прибыли содержат расшифровку по категориям клиентов. Нумерация строк сквозная на два городских листа, все ячейки имеют границы.

**Все налоги розницы и опта объединены на Киеве**, без пропорций работников. Все банковские расходы также относятся на Киев без ограничения складов. На Одессе обе статьи — 0, не заполнять. Настройки фирм остаются нужны для классификации документов.

Старые сохранённые отчёты сохраняют прежние суммы и отборы. Версии с историческими долями налогов сохраняют прежний формат выгрузки. Для отчётов с режимом «все налоги на Киев» действует новая раскладка H/I. Неприменимые нулевые строки скрыты, а неожиданные ненулевые или недоступные статьи показаны после основной таблицы: они входят в итог сайта, но не в ручные формулы H. Чтобы получить новые правила отбора, выполните новый расчёт месяца после обновления Java.

Изменения в Excel меняют только файл. Следующие листы содержат подробные отборы, аудит, МК обоих городов и исходные параметры.

## Если проверяете документы вручную

Для расходов месяца просмотрите минимум предыдущий, выбранный и следующий месяцы документов. Например, для июля — июнь, июль и август. Правильные год и месяц в примечании определяют месяц расхода; без такого периода используется дата документа. Повреждённые или неоднозначные примечания передайте на проверку.

Не суммируйте импортный транспорт повторно: в отчёте он показан отдельно и не входит в операционные расходы. Доходы и возвраты мастер-классов берутся автоматически.

---

Инструкция соответствует интерфейсу lavka-reports 0.9.2. Проверено по коду и формулам файла 07.10.2026. WordPress не вводит новые правила отбора самостоятельно: они требуют обновления Java. Названия кнопок могут отображаться на украинском языке. Публикация и сверка production выполняются отдельно после деплоя.

## Сравнение выбранных месяцев и база отклонений

Версия 0.11.0, локальная проверка 21.10.2026; публикация требует деплоя плагина.

1. Выберите диапазон **«С месяца — По месяц включительно»** и откройте сохранённые отчёты.
2. Нажмите **«Добавить показанные версии в сравнение»**, затем удалите ненужные месяцы. Можно открыть другой диапазон и добавить месяцы оттуда: прежний выбор останется. Максимум — 24 разных месяца, по одной версии каждого.
3. Основная таблица диапазона может показывать старую выбранную версию. Для нового предварительного результата используйте **«Сравнить последний расчёт #…»**. Любую другую сохранённую версию можно добавить из **«Версии месяца»**.
4. Сравнение повторяет **порядок и сквозную нумерацию таблицы менеджера: сначала Киев, затем Одесса**. За основу раскладки берётся самый поздний сравниваемый месяц. Дополнительные исторические статьи, которых в его шаблоне нет, показаны отдельно без изменения основных номеров. По каждому месяцу видны сумма, применённая база, источник/покрытие, разница в грн и процентах.
5. При необходимости введите сумму в **«Ручная база, грн»** напротив статьи и выйдите из поля. Она имеет приоритет над средним для всех сравниваемых месяцев. **Ноль — действительное ручное значение.** Очистите поле, чтобы вернуть автоматическое среднее. Можно вводить отрицательные значения и десятичную запятую. Некорректное значение не сохраняется, поле показывает ошибку.
6. Новые расчёты и открываемые версии автоматически появляются в блоке отклонений. **«Скачать сравнение в Excel»** выгружает городские таблицы с тем же порядком, ручными базами, применёнными средними и отклонениями, а также лист происхождения данных. Обычный шаблон H/I не меняется.

**Как считается автоматическая база.** Для каждого сравниваемого месяца отдельно
берутся четыре предыдущих календарных месяца из сохранённых отчётов. Для октября
2025 это июнь–сентябрь 2025. Сам октябрь и более поздние месяцы исключены; более
старые месяцы не подставляются вместо пропусков. Не требуется добавлять эти четыре
месяца в отображаемое сравнение: история загружается автоматически, без обращения
к ФОЛИО. Используется последняя законченная попытка (COMPLETED/PROVISIONAL), если
она доступна как latest; иначе текущая сохранённая версия. Предварительность и
различия правил/параметров явно предупреждаются. Пропущенный/неудачный latest не
считается успешным расчётом. Точные использованные версии видны в **«История и
правила сравнения»** и в Excel.

По каждой статье достаточно данных **хотя бы за один месяц из четырёх**. Среднее —
сумма имеющихся значений / число месяцев с этими значениями; веса равные.
Покрытие показывает `1/4`, `2/4`, `3/4` или `4/4`. Явный ноль участвует в среднем;
отсутствующая статья не считается нулём. Если ни одного значения нет, появляется
**«Требуется ручной ввод»**. Ошибка загрузки истории обозначается отдельно и не
выдаётся за подтверждённое отсутствие документов. Ручная база позволяет сравнение
даже без истории. Исторические агрегаты не раскладываются на подстатьи по догадке.

Ручные значения — параметры **только сравнения**, а не правки сумм отчёта. Они не
пересчитывают другие строки: например, ручная база аренды не меняет базу итоговых
расходов. Повторённый итог операционных расходов в расходах и в итогах прибыли
использует одно и то же ручное значение.

Выбор, ручные значения и ссылки на версии истории запоминаются для текущей
учётной записи и сайта **в этом браузере**. В другом браузере их нужно задать заново.
Суммы отчётов локально не сохраняются: при загрузке страницы читаются сохранённые
версии по ID. Для уже просмотренного месяца ссылки на историю не меняются сами;
**«Обновить историю»** перечитывает доступные версии четырёх предыдущих месяцев.
Новый расчёт не включает сам себя в базу. Изменения другой вкладки не подменяют
параметры открытой страницы автоматически.

После обновления с 0.10.0 выбранные месяцы сохраняются, а прежняя вручную
зафиксированная база из всего периода заменяется правилом предыдущих четырёх
месяцев. Это изменение аналитического сравнения, не финансового отчёта.

Процент = `(значение − база) / |база| × 100%`. При нулевой базе процент недоступен,
кроме `0 против 0 → 0%`; денежная разница остаётся видна. Плюс/минус означает
рост/снижение значения, а не улучшение/ухудшение. Среднее для процента не округляется
предварительно; вывод — два знака. В Excel процент записан в процентных пунктах
(50 означает 50%). Правила отбора, публикация версий, суммы Java и ФОЛИО не меняются.
