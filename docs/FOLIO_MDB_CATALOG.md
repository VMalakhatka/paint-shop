# Каталог MDB ФОЛИО

Проверено: 2026-10-22. Владелец фактов: `$folio-access-catalog`; при будущей реализации MSSQL — `$work-with-folio-mssql`, сайт — `$lavka-woo`.

По запросу владельца создан персональный skill `folio-access-catalog` в `~/.codex/skills/folio-access-catalog`. Его `SKILL.md` задаёт порядок приёма следующих MDB, `references/catalog-index.md` — реестр, `references/queries-ts/analysis.md` — назначение объектов, а `catalog.md` и `catalog.json` рядом — SQL и метаданные. Skill и подробные каталоги установлены локально; этот Git-документ фиксирует маршрут и статус, а не резервную копию персонального skill.

Первый источник: `Запросы-TS.mdb`, 35 721 216 байт, SHA-256 `3a1b084d878632625312edc9b4038c4e53ef185dcdb21722aeb100aca436cb59`.

Извлечение выполнено офлайн через mdbtools и Jackcess readOnly, без исполнения SQL, макросов или обращения к связанным таблицам. Хеш исходника после чтения совпадает. Структура skill, охват 33 запросов и 9 макросов и отсутствие вероятных секретов проверены.

Существенные результаты анализа: у `Валютная_Цена_Плюс` нет фильтра склада; запросы `Учётная_Цена_*` являются SELECT; «Неправильная Валютная Цена» отбирает ненулевое в смысле NOT NULL поле без проверки правильности; источник `dbo_SCL_ARTC-BB` отсутствует среди связей файла. Эти особенности не исправлялись. Плановые APPEND формируют локальные списки, а создание документов движения ими не подтверждено.

## Что ещё требуется

Для каждого объекта источник загрузки входных данных и условие запуска ожидают пояснений владельца. Для полного разбора макросов нужен текстовый экспорт их определений из Access; бинарные упоминания запросов не доказывают цепочку исполнения. Процедура безопасного экспорта сохранена в skill, `references/offline-extraction.md`.

Новые MDB добавляются по имени и хешу отдельными версиями. Их содержимое — источник анализа, а не разрешение выполнять операции. 22.10.2026 по отдельному подтверждению владельца подготовлена [реализация «Валютная цена Украина»](api/FOLIO_CURRENCY_UA.md): Excel/CSV → предпросмотр → оба исходных UPDATE одной транзакцией. Production-публикация и живые UPDATE не выполнялись. Остальные функции не реализованы. Ранее созданная функция экспорта карточек является отдельной работой.
