## Постоянное правило: российская база не поддерживается

Решение владельца от 23.10.2026 действует для всех текущих и будущих переносов
макросов и запросов ФОЛИО: действия для `Paint_Rus` всегда пропускать. Рабочая база —
`Paint_Ua`; повторное согласование исключения Paint_Rus не требуется.
Проверять фактическую БД назначения в SQL и linked tables, а не только суффикс `-RUS`
или регистр имени. Пропущенные RUS-действия не перенаправлять в Paint_Ua: это может
повторно применить изменения. Исходный SQL и порядок макроса сохранять в каталоге
как исторические свидетельства, помечая исключение из реализации.
Если оставшийся UA-запрос зависит от российской базы, не исполнять его с урезанным
JOIN или придуманной заменой источника; зафиксировать эту зависимость отдельно.
Исторические инструкции и эксперименты с Paint_Rus не означают возобновление её
поддержки и не разрешают автоматически выбирать её для новых сценариев.

Источники из метаданных найдены среди объектов соответствующего файла; работоспособность связанных таблиц на сервере этим не проверяется. Файлы исследованы офлайн, их SHA-256 после чтения не изменились. Исходные MDB, рабочие данные и строки подключения в skill или Git не переносились.

В `Запросы_из_Фолио-TS.mdb` есть массовые изменения карточек/цен и 12 DELETE связанных записей, включая удаление конкретного Key. В `Розница-TS.mdb` есть расчёт розницы, промежуточная Price, разборки, конвертация валют, четыре DELETE и два CREATE TABLE. Название `ОПТ+3%` в одном UPDATE соответствует коэффициенту 0.97; это сохранено как исходная логика, без исправления. Предметные разборы с точными именами запросов находятся в skill.

Из 55 макросов этих двух MDB четыре макроса менеджера теперь имеют `ACTIONS_DECODED_OFFLINE`: их 10 действий извлечены из MSysAccessObjects через Jackcess/CFB и сверены независимым парсером. Остальные 51 имеют `UNRESOLVED_STORAGE`. Первоначальный mdbtools-экспорт не показывал BIG_BINARY; совпадения имён сами по себе не использовались как доказательство действий. В `Розница-TS.mdb` обнаружен `Module1`, тело не извлечено; SQL вызывает `okrugl(...)`, определение которой ещё нужно получить. Её принадлежность именно Module1 пока не установлена.

## Салимон: источник «Сборка накладная»

22.10.2026 владелец уточнил источник сценария №6: Салимон_Запросы_из_Фолио.mdb. Офлайн-проверка подтвердила макрос «Сборка накладная» (ObjectId -2147483603) и локальную таблицу «для сборки». Все 53 SQL нового файла восстановлены; исходный SHA-256 после чтения совпал. Исторические SQL-каталоги других MDB сохранены без изменений.

В skill описаны 18 связанных по назначению запросов сборки, их поля, формулы и локальные таблицы назначения. «Сборка накладная» содержит 16 OpenQuery в восстановленном порядке, статус `ACTIONS_DECODED_OFFLINE`; оставшиеся 14 макросов имеют `UNRESOLVED_STORAGE`. Все записи цепочки направлены в локальные промежуточные таблицы, прямого создания документа ФОЛИО в ней нет. Действия извлечены из бинарных записей и сверены вторым парсером, без запуска Access. Отдельный `Запрос1` ссылается на `[dto].SCL_MOVE`, отсутствующую среди зарегистрированных источников MDB; доступность не подтверждена. Исполнение запросов, создание документов и реализация сайта не выполнялись.

## Сценарии менеджера

22.10.2026 владелец передал и затем исправил `Макросы.xls`: `Лист1!A2:D8`, семь записей, из них шесть включены в текущий разбор. SHA-256 исправленной версии `176f0db0fe1ba58aeaca1226dc738e5f52324c0bb3307a93b388d3c9568c53be`, размер 29 696 байт. Файл прочитан без изменений; Лист2/Лист3 пусты. В персональном skill `references/manager-workflows.md` и `.json` содержат текущие ячейки, ObjectId, подтверждённые исправления имён и исторический снимок прежних значений.

Для строк 1–6 теперь прямо указаны MDB: наименование, группы, единицы измерения, описание товара, выборка по главному артикулу и «Сборка накладная». Найдены все шесть входных таблиц и объекты: **пять макросов и один SELECT-запрос**. Владелец подтвердил ошибки ввода менеджера: `группа` соответствует макросу `Группы`, `Един_Измер` — макросу `ЕдинИзмер`; имена таблиц при этом верны. Заголовок XLS «Макросы» не меняет фактический тип строки 5 — SELECT. Источник сборки прямо указан как Салимон_Запросы_из_Фолио.mdb; прежнее значение Розница-TS.exe осталось только в истории.

Строка 7 КиевОпт в исправленной таблице помечена «этот не анализировать» и исключена из текущего разбора. Её исходник не запрашивается; прежняя отметка об отсутствующем MDB больше не является открытым вопросом этой задачи.

Использование сценариев и соответствие имён подтверждены; действия пяти макросов (26 OpenQuery) теперь восстановлены из MDB. Точные цепочки и свидетельства находятся в skill, `references/manager-actions.md` и соответствующих `manager-actions.json`. Четыре макроса карточек включают Paint_Ua и Paint_Rus. У описания товара сначала выполняются APPEND обеих баз, затем UPDATE. Для сайта владелец подтвердил только Paint_Ua: новые ключи добавить, существующие обновить. Остальные объекты каталога не помечены неиспользуемыми. Источники внешней загрузки таблиц и условия запуска пока ожидают пояснений владельца. Владелец подтвердил реализацию шести операций таблицы без КиевОпт, только Paint_Ua. Код подготовлен локально; подробности и оставшиеся уточнения сборки — в [инструкции](FOLIO_MANAGER_OPERATIONS.md).

## Что ещё требуется

Для каждого нового объекта источник загрузки входных данных и условие запуска ожидают пояснений владельца. Пять макросов менеджера имеют строгий офлайн-разбор действий; для остальных нужен дальнейший разбор или текстовый экспорт из Access. Бинарные упоминания запросов не доказывают цепочку исполнения. Для розничных формул дополнительно нужен экспорт VBA и определение `okrugl`. Процедура безопасного экспорта сохранена в skill, `references/offline-extraction.md`. За пределами шести выбранных операций новые функции по этим MDB не реализовывались.

Новые MDB добавляются по имени и хешу отдельными версиями. Их содержимое — источник анализа, а не разрешение выполнять операции. 22.10.2026 по отдельному подтверждению владельца подготовлена [реализация «Валютная цена Украина»](api/FOLIO_CURRENCY_UA.md): Excel/CSV → предпросмотр → оба исходных UPDATE одной транзакцией. Production-публикация и живые UPDATE не выполнялись. Для шести выбранных операций подготовлены [интерфейс и Java API](FOLIO_MANAGER_OPERATIONS.md), только Paint_Ua. Упрощённый ввод сборки ожидает уточнения менеджерских колонок, численная сверка с Access ещё не выполнена. Ранее созданная функция экспорта карточек является отдельной работой.
