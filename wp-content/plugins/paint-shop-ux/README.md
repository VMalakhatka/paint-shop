# Paint Shop UX

Владелец каталога, карточек, навигации и обычных информационных страниц Lavka. Не изменяет документы,
остатки, цены, распределение складов или Java. Пользовательские действия описаны
в [оптовой инструкции](../../../docs/WHOLESALE_CUSTOMER_GUIDE_UK.md).

## Единый поиск и подсказки (2026-09-24)

В каталоге остаётся поле над фильтрами. Сравнение исходных реализаций подтвердило:
оба поиска использовали Relevanssi, но sidebar `core/search` отправлял глобальный
`s`, а форма каталога сохраняла категорию и условия. Дублирующие classic/Woo/core
search widgets теперь подавляются при выводе каталога, без удаления их настроек;
поиск на карточке товара и остальных страницах не меняется.

`inc/catalog-search.php` обслуживает публичный read-only admin-AJAX
`psu_catalog_suggest`: 2–100 символов, максимум шесть опубликованных поисково
видимых товаров, точный SKU (включая родителя вариации) первым, затем текущий индекс
Relevanssi. Категория с потомками, поставщик, unit, склады, наличие и цена
пересекаются. Неизвестные термины дают пустой результат, а не глобальный поиск.
Цена берётся через Woo `get_price_html()` для текущего пользователя. Ответ
private/no-store, без общего кэша цен, без Java/ФОЛИО и изменений корзины.
Диапазон цены сохраняет прежний контракт фильтра Woo (`_price`).

Клиент задерживает запрос на 300 мс, отменяет устаревшие запросы, поддерживает
стрелки/Enter/Escape и обычную отправку формы при ошибке. Фото и область подсказок
имеют фиксированные размеры с адаптацией к экрану/клавиатуре. Дублирование поисков
не означает перенос настроек индекса: существующий индекс и индексируемые поля
сохранены, новый полный rebuild для этой доработки не требуется.

Дополнительные поля свёрнуты по умолчанию на компьютере и телефоне. Скрытие не
очищает условия; серверный счётчик показывает активные группы фильтров.
Сортировка поставщиков применяется к просмотру каталога без текстового поиска,
но не перезаписывает релевантность индексированного поиска.

Локальные проверки: `tests/catalog-search-local.php` (временные товары с cleanup),
`tests/catalog-search-session-local.php` prepare/cleanup и
`tests/catalog-search.spec.cjs` (Chrome 1280/390, реальное фото, клавиатура,
штрихкод, отбор, fallback при HTTP 503, цена оптовика и заголовки кэша).
Существующие `catalog-filters.php` и `catalog-units-local.php` проверяют регрессии.
Поставка в существующем `paint-shop-ux` и MU-файлах, новых плагинов/настроек нет.
Production и публикация справки ожидают отдельного деплоя. Откат: revert коммита,
повторный обычный deploy; настройки sidebar widgets не удалены.

## Фильтр единиц измерения

MU `psu-search-filters.php` 1.6.0 выводит «Одиниця виміру» и принимает `unit=<значение>`.
Java `SyncServiceImpl.mapDtoToWooProduct` записывает `edinIzmer` в `_edin_izmer`,
а PHP `lavka-total-sync` записывает его в глобальный атрибут `pa_edin_izmer`.
Фильтр использует непустую `_edin_izmer`; при её отсутствии/пустом значении берёт
атрибут. Название/фасовка не разбираются. С 2026-09-24 очевидные варианты записи
объединены в отображении и отборе: `50мл`, `50 мл`, неразрывный пробел, `50МЛ.`
дают одну опцию `50 мл`; `шт`/`шт.` дают `шт`. Распознаются числовые мл/л/мг/г/гр/кг/шт.
В GET форма передаёт единое написание; старые URL с исходным значением работают.
SQL и Relevanssi сравнивают все исходные варианты через prepared IN, сохраняя
приоритет meta над атрибутом. Словарь вариантов читается один раз на запрос,
включая search-only товары, без persistent cache. Данные Woo/ФОЛИО не меняются.
Объёмы не пересчитываются; `0,05л` не объединяется с `50мл`, `гр` не заменяется
на `г`, префиксы сохраняются, `2,5г` не превращается в `25г`.

Список ограничен опубликованными видимыми товарами категории и её потомков;
на общей витрине/поиске используются все доступные значения Woo. Другие
выбранные фильтры не скрывают альтернативные единицы из списка. Сортировка
естественная по названию. Один UNION-запрос получает distinct значения, не все товары;
товарные объекты для списка не загружаются. Значения не ограничиваются текущей
страницей выдачи, отдельного persistent cache или запроса в Java нет.

Поставщики и склады также ограничены опубликованными видимыми товарами ветки,
с сохранением административной видимости/порядка поставщиков. Уже выбранное
значение остаётся доступным для сброса, даже если в ветке больше нет товаров.
Выбранные условия видны отдельно под формой и над товарами, в том числе при
свёрнутой панели и пустой выдаче: поиск, единица, поставщик, каждый склад,
наличие, нижняя/верхняя цена. Ссылки удаляют ровно одно условие, сбрасывая
пагинацию. «Скинути все» очищает все ограничения, но сохраняет категорию,
сортировку и размер страницы. Показывается применённое URL-состояние, а не
несохранённые изменения формы. Работает без JavaScript и без новых AJAX запросов.

Проверки: `tests/clean-filters-local.php` (алиасы meta/attribute, приоритет,
неизменность данных, SQL/Relevanssi, состав chips и URL),
`tests/clean-filters.spec.cjs` (1280/390/320, оптовик, гость без JS, пустая выдача,
сброс одного из двух складов и всех ограничений). Справка обновлена в коде;
production-публикация требует отдельного обычного deploy, перестройка индекса
и изменения Java не нужны.

Отбор добавляется через SQL EXISTS с AND к существующим условиям категории,
поставщика, наличия, цены и поиска. Одна функция формирует условие для WP_Query
и `relevanssi_post_query_filter`; параметр передаётся через конкретный основной
query; для подсказок явно разрешён secondary query с `_psu_suggest`, остальные
вторичные поиски не затронуты. Фильтрация выполняется до подсчёта
и пагинации, без загрузки всех product IDs и без дублей при двух источниках.
Он не использует `filter_edin_izmer` и
`wc_product_attributes_lookup`: синхронизация пишет term relationships и meta
атрибута напрямую, поэтому полнота вторичного индекса Woo не гарантирована.
Товары без единицы не исчезают без отбора. Неизвестное значение даёт пустую выдачу с
возможностью сбросить выбор; array input игнорируется. Пагинация и выбор 12/24/48
сохраняют unit; повторное применение формы начинает выдачу с первой страницы.

привязок `pa_edin_izmer`, но значения присутствуют в `_edin_izmer`.
В частности, `KR-79406` имеет `250мл`, а `KR-49602` из «Клей» имеет `125мл`.

автоматически и не запускает синхронизацию. Локально расхождений meta/атрибута
не найдено; при конфликте действует описанный выше приоритет, а не вывод о свежести.

## Стабильные версии ресурсов Stock Locations

С версии Paint Shop UX 1.3.2 модуль `inc/slw-assets.php` заменяет timestamp в URL
известных frontend CSS/JS Stock Locations на `SLW_PLUGIN_VERSION` + первые 16
символов SHA-256 файла. Проверено локально 2026-09-17 со Stock Locations 3.2.1.
Содержимое перечитывается один раз на ресурс за PHP-запрос, без persistent cache:
изменение файла обнаруживается и при сохранённом mtime; обновление версии SLW также
меняет URL. Локальная настройка или миграция не требуется.

| Handle | Файл SLW | Зависимости | Условие подключения владельцем |
|---|---|---|---|
| `slw-frontend-styles` | `css/frontend-style.css` | нет | frontend |
| `slw-common-styles` | `css/common-style.css` | нет | frontend |
| `slw-common-scripts` | `js/common.js` | jquery | frontend |
| `slw-jquery-blockui` | `js/jquery.blockUI.js` | jquery | frontend |
| `slw-frontend-product-underscore` | `js/underscore-min.js` | jquery | карточка товара |
| `slw-frontend-product-scripts` | `js/product.js` | jquery-blockui | карточка товара |
| `slw-archive-scripts` | `js/archive.js` | jquery-blockui | архив location |
| `slw-frontend-cart-scripts` | `js/cart.js` | jquery-blockui | SLW show_in_cart=yes |

Фильтры `script_loader_src`/`style_loader_src` меняют только `ver` перед выводом.
Регистрация, dependencies, порядок, footer placement, inline/localized данные
складов, цены, права и корзина остаются у прежних владельцев. Ничего не dequeue;
это не дедупликация двух blockUI. Admin, неизвестные handles, изменённые пути/CDN
под знакомым handle и отсутствующий/нечитаемый файл остаются без вмешательства.
Если SLW отключён, модуль не действует. Проверка host/port/path ограничивает
соответствие конкретным файлом установленного плагина.

Серверные cache headers не меняются. Local nginx требует revalidation
(`no-cache, public, must-revalidate, proxy-revalidate`), поэтому повторное посещение
получает 304, а не гарантированные ноль сетевых обращений. Browser Resource Timing
для четырёх общих файлов: 10 046 → 1 200 байт при повторном переходе, тела файлов
повторно не передаются. Это счётчик браузера с условным учётом заголовков, не сетевой
packet capture и не процент ускорения сайта. Полные условия и ограничения — в
[отчёте скорости](../../../docs/SITE_PERFORMANCE_AUDIT_2026-09-14.md).

Локальная проверка: `wp --exec='define("DISABLE_WP_CRON",true);define("WP_HTTP_BLOCK_EXTERNAL",true);' eval-file wp-content/plugins/paint-shop-ux/tests/slw-assets-local.php`.
33 проверки охватывают стабильность, изменение content/version, сохранённый mtime,
неизменность registry/inline data, admin, неизвестные ресурсы и missing file.
Для browser cache test не отключать кеш и не использовать request interception,
который его отключает. Проверять первый визит и обычный переход/повторный визит;
hard reload не является тёплой навигацией.

Откат только этой оптимизации: убрать подключение `inc/slw-assets.php` из основного
файла Paint Shop UX и сам модуль; сохранить меню/пагинацию 1.3.1. SLW снова отдаст
свои timestamp URL. Не отключать Paint Shop UX целиком и не сбрасывать общий кеш.
Изменений пользовательского пути и строк интерфейса нет: оптовая инструкция и
«Як замовляти» сохраняют прежнее содержание. Production-публикация 1.3.2 в этой
работе не выполнялась.

## Ленивое меню категорий

Размер выдачи обслуживает MU `psu-force-per-page.php` 1.2.0. Приоритет:
валидный целочисленный `pp` (6–120), затем `per_page` (1–200), затем
`psu_products_per_page`/24. Cookies `psu_cols`/`psu_rows` игнорируются; измерение
колонок и автоматический reload удалены. Адаптивные колонки задаёт `assets/catalog-cards.css` (с 1.6.0 сетка перенесена из child theme).
Этот plugin выводит 12/24/48, возвращает на первую страницу при смене размера
и сохраняет остальные параметры; фильтр MU сохраняет выбранный параметр.
Основной query и Woo используют одно значение в обоих полях размера страницы.
Вторичные запросы, обычный поиск записей, admin, single и feed не меняются.

Ленивая загрузка реализована локально 2026-09-15; собственный виджет добавлен
2026-09-17 в версии 1.3.0. В тот же день после deploy и отдельного разрешения
владельца выполнен перенос production-виджета; WPB отключён после аудита зависимостей.
Результат и границы проверки записаны в [отчёте](../../../docs/CATEGORY_MENU_LOCAL_VERIFICATION_2026-09-15.md).

### Видимость категорий

**Вигляд → Категорії Лавки → Приховані категорії**: дерево по алфавиту с кнопками
плюс/минус и галочками. Галочка означает скрытие категории вместе с подгруппами;
унаследованные галочки недоступны до снятия галочки родителя. Выбор сохраняется
при поиске, раскрытии и подгрузке. Сверху перечислены явные исключения с кнопкой
удаления из списка; поиск показывает полный путь. Нажмите **Зберегти зміни**.
Исключается вся выбранная ветка, в том числе при открытии её страницы
и при запросе подгрупп через REST. Пустой список возвращает обычную видимость.
Настройка общая для меню и плиток категорий, хранится в `psu_category_menu_excluded`; требуется
`edit_theme_options`. Категории, товары и прямые ссылки не удаляются.

С 2026-09-24 явные исключения также применяются к Woo-плиткам главной/магазина,
подкатегориям (включая расширенный архив) и shortcode `[product_categories]`.
Отбор точечный, без глобального фильтра `get_terms`: админка, карточки товаров
и прямые страницы не блокируются. При непустом списке исключений внешний кэш
Woo hierarchy обходится, чтобы не вернуть старые плитки; штатный кэш WP term query
сохраняется. Имеющиеся исключения других фильтров объединяются с нашими.
Проверка тёплого кэша, потомков и гостевого вывода: `tests/category-tiles-local.php`.
Проверено локально 2026-09-24: 19 PHP-проверок и гостевой браузер при 1280/390 px,
включая исчезновение плитки после выбора и возврат после снятия исключения.
Production проверен только на чтение; исправление и справка ожидают deploy.

При включённом **Hide empty categories** пустые ветки не выводятся даже для
текущей страницы. Родители с товарами в доступных подгруппах остаются.
В 1.3.3 индекс считает непосредственно опубликованные, видимые в каталоге товары,
а не raw `term_taxonomy.count`: 2026-09-23 production read-only подтвердил
27 опубликованных записей в «Без названия» при Woo catalogue count=0.
Исправление 1.3.2 закрывало active-path pin, но не различие этих счётчиков.
Один агрегирующий запрос при построении кэша учитывает exclude-from-catalog и
глобальное Woo hide-out-of-stock; нет запросов товаров для каждой категории.
Прямые количества позволяют убрать родителей, если товары остались только в
исключённых подгруппах. Изменения product_visibility и product_count_product_cat
сбрасывают namespace; настройка Woo наличия также входит в ключ кэша.
Явные исключения действуют независимо от этой галочки. Список исключений входит
в ключ кэша; после сохранения настройка применяется без ручной очистки кэша меню.
Внешний полностраничный кэш, если включён, очищается штатным способом.
Регрессия: `tests/category-visibility-local.php` (локальные фикстуры с очисткой).

Регрессия 1.3.3 дополнена скрытыми/search-only товарами, черновиками,
глобальным hide-out-of-stock, admin branch pagination и наследованием галочек.

агрегата: «Без названия» невидима, 4643 строки категорий, 257 мс на один холодный
расчёт (не среднее время и не время загрузки страницы). Кэш рассчитанного индекса
используется последующими запросами; production-код и настройки не изменялись.

`node tests/category-visibility.spec.cjs`, затем обязательно
`tests/category-visibility-fixture-local.php cleanup` через локальный WP CLI.
Фикстура хранит временную сессию администратора только в закрытом файле /tmp.
Не запускать проверку всего дерева одновременно с браузерным изменением исключений.
Production в этой задаче не изменялся; изменения ожидают deploy.

`inc/category-widget.php` регистрирует **«Категорії Лавки»** (`psu_category_menu`)
в штатном экране виджетов WordPress. Настройки находятся в
`widget_psu_category_menu`: title, orderby, order, hide_empty, show_count. Данные
категорий остаются в WooCommerce `product_cat`. Работа собственного виджета,
его GET endpoint, JS и CSS не зависит от активного WPB.

`inc/category-menu.php` содержит общий renderer и временный адаптер существующего
`wpb_wmca_accordion_widget`. До переноса адаптер перехватывает
`widget_display_callback` до WPB walker и читает настройки опубликованного блока
taxonomy/product_cat. Другие виджеты и неподдерживаемые настройки (например WPB
hide_out_of_stock или неизвестная сортировка) остаются без изменений.

Начальный HTML содержит до 30 корней за страницу, текущую ветку и до 60 обычных
категорий суммарно. Если текущая ветка не поместилась в порцию, её звенья добавляются
отдельно: редкое исключение для особо глубокого дерева. Нет скрытой полной копии
дерева в HTML/JSON. Остальные строки открывает «Ще категорії». При загрузке
последующих порций уже показанная активная категория не дублируется и переносится
на своё место в сортировке с сохранением раскрытого поддерева.

Названия являются обычными ссылками. Отдельные кнопки раскрытия поддерживают
Tab/Enter/Space, aria-expanded/controls, loading, ошибку и повтор. Повторные клики
используют один незавершённый запрос; уже загруженные ветки повторно не запрашиваются.
Без JS кнопки скрыты, ссылки работают; дочерние разделы доступны на страницах
категорий. В кабинете, корзине и checkout выводится компактная ссылка в каталог.
На мобильном меню остаётся в штатной позиции sidebar темы; оно не переносится
выше товаров в рамках этой задачи.

### API и кэш

`GET /wp-json/paint-shop-ux/v1/categories?widget=<active-widget-id>&parent=<term-id>&offset=0&locale=uk`

- Только общедоступные category ID/name/URL, опциональный существующий счётчик,
  признак детей и next offset. Не принимает IDs клиента/цены/остатки и не пишет ФОЛИО.
- Максимум 30 непосредственных детей. Несуществующая/скрытая категория: 404;
  недопустимые параметры: 400; лист/конец списка: items=[], next=null.
- Имена/ссылки читаются через get_terms/get_term_link. Для SQL LIMIT используется
  include непосредственных child IDs, а не parent+number: WordPress в последнем
  случае не ограничивает SQL. Стабильный дополнительный ключ сортировки: term_id.
- При холодном кэше **один общий запрос ID/parent/count всей product_cat** строит
  компактный серверный индекс видимости. Это необходимо, чтобы hide_empty сохранял
  пустых родителей непустых потомков без N+1 и обхода всего дерева при каждом клике.
  Имена, ссылки, описания и HTML всех категорий при этом не формируются.
  Тёплый запрос читает кэш ветки; результат ограничен порцией. Иерархические ссылки
  используют предварительную пакетную загрузку предков, без запроса на каждую строку.
- Transients TTL 1 час; ключ включает версию данных/кода, blog ID, locale, home URL,
  permalink configuration, настройки виджета, parent/offset/limit. В нём нет
  пользовательских данных. HTTP-ответ no-store; общий кэш находится на сервере.
- В 1.3.1 общий кэш хранит канонические category URL и slug. Единственный владелец
  quick-order rewrite — `PCQO_Category_Links` в MU `pc-wholesale-quick-order.php`;
  дублирование в child theme удалено. Scoped `catalogue_url()` подавляет только
  собственный rewrite, сохраняя остальные `term_link` filters. Версия 1.3.1 меняет
  только namespace меню; глобальный cache flush не нужен.
- На разрешённой странице `[pc_quick_order]` renderer отдельно проецирует ссылки
  после чтения кэша. JS передаёт публичный `quick_order_page` в REST, поэтому
  подгружаемые дети и следующие порции используют тот же контекст. Без параметра
  REST всегда возвращает каталог. Ненулевой ID должен указывать на опубликованную
  страницу без пароля с этим shortcode, иначе 404. Это публичная проекция URL,
  не предоставление доступа: содержимое быстрого заказа по-прежнему проверяет
  `pc_wholesale_customer_can_access()`. Произвольный redirect URL не принимается.
- clean_term_cache/clean_taxonomy_cache и изменение order termmeta меняют namespace.
  WordPress count update/recount после синхронизации тоже вызывает clean_term_cache.
  В массовой операции смена namespace происходит в начале и на shutdown; во время
  изменения новые данные не кэшируются. Прямые SQL-записи в категории в обход hooks
  требуют штатной очистки term cache либо `PSU_Category_Menu::bump_version()`.
- Локальная витрина использует uk и одну общую taxonomy; RU gettext проверяется
  отдельно без смены настройки сайта. Endpoint принимает только установленные
  locale. Polylang/WPML и отдельные языковые taxonomy здесь не установлены и не
  сертифицированы; при их добавлении нужен отдельный адаптер language context.

Собственный JS подключается лишь при выводе дерева. Пока WPB активен, его JS удаляется перед footer
scripts только если в запросе не отрисовался другой WPB shortcode и нет посторонних
JS-зависимостей от его handles. Старый CSS оставлен: на этапе head ещё нельзя
доказать отсутствие WPB shortcode ниже на странице. После отключения WPB его CSS
и JS не подключаются вообще. Сторонние файлы не изменены.

### Переход на собственный виджет

1. После deploy Paint Shop UX 1.3.0 оставьте WPB активным. Откройте
   **Вигляд → Категорії Лавки** (`themes.php?page=psu-category-menu`). Нужна
   capability `edit_theme_options`; роль покупателя не подходит.
2. Проверьте список замен и нажмите **«Замінити віджети категорій»**. Это отдельный
   POST с nonce и сверкой плана; обычное открытие витрины не запускает перенос.
   Сохраняются заголовок, сортировка, флаги, позиция в каждой активной sidebar.
   Уже существующие собственные экземпляры и остальные виджеты не перезаписываются.
   Неактивные/осиротевшие области и неподдерживаемые WPB-виджеты не переносятся.
3. Откройте **Вигляд → Віджети**: новый виджет называется **«Категорії Лавки»**.
   Заголовок на витрине остаётся прежним, пока вы сами его не измените.
   Проверьте раскрытие веток, ссылки, текущую категорию и телефон. Ранее открытые
   страницы обновите: запросы со старым ID виджета после замены отклоняются.
4. Перед деактивацией WPB проверьте остальные sidebars, WPB shortcodes в страницах,
   блоках/шаблонах, builder metadata и PHP темы/собственных плагинов. Установка
   собственного виджета сама по себе не доказывает отсутствие других зависимостей.
5. Только после этой проверки отключите WPB в **Плагіни**. Перенос не отключает и
   не удаляет его автоматически, не удаляет блоки WPB, товары или категории.

`inc/category-menu-migration.php` сохраняет журнал `psu_category_menu_migration_v1`
до первой записи: исходные и целевые настройки, список замен, время и статус
`prepared`/`completed`/`restored`. Сначала записываются новые экземпляры, потом
sidebars. Ошибка записи не считается успехом. Повторный перенос не создаёт дубли.
Блокировка `psu_category_menu_migration_lock` исключает параллельные запуски.

Откат: сначала активируйте WPB, затем на той же странице нажмите
**«Відновити віджети WPB»**. Откат возможен и после прерванной записи (`prepared`).
Он откажется перезаписывать более поздние ручные изменения sidebars/собственных
виджетов; в таком случае сравните журнал и перенесите нужный старый виджет вручную.
Допускается только штатное удаление/возврат исходных перенесённых WPB-экземпляров
из списка неактивных при выключении/включении плагина. Другие изменения не игнорируются.
При аварийном завершении PHP lock может остаться. Удалять только этот lock через
WP-CLI можно после проверки, что переноса уже нет в работе; сам журнал не удалять.
Деактивация или откат plugin-кода не выполняют обратный перенос настроек.

отдельное имя и не регистрирует hooks. Первая сборка namespace не означает холодный
WordPress: core caches общие. WPB включать для этого теста не нужно.

## Conditional social assets (2026-09-27)

`inc/social-assets.php` removes WP Social's four global frontend assets only on
the front page, shop, product taxonomies and product search without known social
placements. Account, login, checkout, single products and other pages retain the
vendor behavior. Fixed share placements, active login/share/counter widgets,
Elementor and WP Social Pro conservatively retain assets. Unknown vendor handles
also fail open. Direct custom theme integrations can return true from
`psu_social_assets_required` to retain the head assets.

Social markup rendered through content, shortcodes or text/block widgets restores
the registered styles and footer scripts, retaining vendor dependencies and
localized nonces. Styles print once before late markup. No vendor files, settings,
roles, orders or customer workflows change; no new help text or translation is needed.

Local regression: `tests/conditional-assets-local.php` (WP-CLI with external HTTP
and cron disabled), `tests/conditional-assets.spec.cjs` (Playwright). The browser
test requires the existing `catalog-search-session-local.php` temporary wholesale
session; always run its `cleanup` afterwards. Import POSTs are intercepted, not
sent to WordPress. See the performance audit for measured scope and deploy checks.

## Собственная страница товара (2026-10-14)

С версии 1.4.0 `inc/single-product.php` выбирает собственный `templates/content-single-product.php`
только на single product и заменяет стандартные/GeneratePress Woo wrappers.
`assets/single-product.css` задаёт двухколоночный верх, мобильную колонку и подробности
ниже. Каталог, кабинет, cart и checkout этим адаптером не меняются.
Общая PHP-оболочка пока остаётся у активной темы; это этап миграции, а не
самостоятельная тема. С 1.7.0 шапка и меню также принадлежат Paint Shop UX. С 1.5.0 футером владеет собственный модуль (см. раздел ниже). Слоты галереи/summary/details сохраняют все пять Woo hooks

Названия и SKU теперь доступны также в related/upsell loops. Paint Core получает
`pcux_catalog_assets_required=true` для этих списков, чтобы работали прежние
кнопки количества и добавления. На остальных страницах значение фильтра сохраняется.

`assets/single-product.js` заменяет legacy single AJAX только на новой странице:
один запрос к Woo add_to_cart для simple, pending state, успешное обновление
quantity cap и счётчика. Отказ не уменьшает остаток. При неизвестном результате
показывает ссылку на корзину и не повторяет POST автоматически. Остальные типы и
отключённый JavaScript используют native Woo forms. UK/RU строки входят в plugin i18n.

Проверено локально 2026-10-14: `tests/single-product-local.php` — 34 проверки;
`tests/single-product.spec.cjs` — гость, оптовая роль и customer на 1440/768/390/320,
галерея/lightbox, tabs, related controls, совпадение role prices, справка,
удаление parent CSS, non-simple native submit и просмотр без JS. Пять ответов
покупки перехвачены: success/pending, rejection, HTTP failure, invalid JSON и
исчерпание лимита. Реальных изменений корзин, заказов, ФОЛИО и production нет.
Это не проверка реальной покупки, доставки/оплаты либо выбора вариантов товара.

До browser test подготовить `tests/single-product-browser-session-local.php` через
WP-CLI с `DISABLE_WP_CRON`/`WP_HTTP_BLOCK_EXTERNAL`. Это создаёт короткие локальные
токены существующих ролей без правки профилей; в любом исходе выполнить тот же
файл с аргументом `cleanup`. Секретный fixture остаётся в `/tmp`, не выводится и
не коммитится. `PSU_PRODUCT_BASE` задаёт локальный тестовый origin, по умолчанию
`http://127.0.0.1:8088`; при тестовом переносе origin сохранять native COOKIEHASH
локального `paint.local`. Только runtime-константы, без записи options.
`PSU_PRODUCT_OUTPUT` меняет временный каталог отчёта/снимков.
Фильтр `psu_single_product_enabled=false` до `wp` возвращает стандартный шаблон,
wrappers и legacy scripts. Новые options, migration, activation и rebuild индекса
не нужны: Paint Shop UX уже активирован и входит в deploy manifest. Для выпуска
нужны обычный согласованный deploy plugin/paint-core и MU help/languages/image,
проверка страницы под гостем/оптовой ролью и шапки/футера. Канон и код справки
обновлены; production-публикация в этой задаче не выполнялась.

## Checkout comfort (2026-10-23; 1.9.2)

`inc/checkout-comfort.php` presents native Woo login and an explanation of the
existing automatic email account workflow before classic checkout. Current
production account creation at checkout is disabled in Woo settings; the MU
`pc-guest-customer-register.php` owns automatic guest account creation instead.
The login reminder is enabled at runtime only on checkout; no stored options
change. Existing account access still requires authentication. Wholesale users
must sign in before checkout to receive their own prices/conditions.

MU version 1.1.0 associates guests strictly by valid billing email, never phone.
Existing profiles, roles and Folio mapping remain unchanged (Woo may update its
own `wc_last_active` bookkeeping). Only newly created customers receive billing,
shipping and default Internet client data. Association is saved before mail;
`_pc_guest_customer_account_created` distinguishes new vs existing accounts.
The mail flag now observes `woocommerce_email_sent`; acceptance by transport is
not proof of inbox delivery. Reprocessing an attached order never creates or
emails a second account. The thank-you notice checks order ownership or secret
order key, distinguishes creation from association, and offers password recovery
when mail fails. No automatic authentication is granted by this workflow.

Email remains required and validated. For every actual shipping package selected
as `local_pickup` (including NP-generated rates), the UI hides street, extra
address, city, state and postcode. Server validation removes their required and format
errors (a hidden stale postcode must not block pickup); contact/country/shipping
errors are preserved. Mixed delivery,
unknown rate IDs or incomplete selections retain normal validation. Switching
back to delivery restores requirements, including country locale changes.
No Nova Poshta API, payment gateway, price or stock algorithm was changed.

The existing mobile cart bar is now <=767px and has a 44px crossed-eye button.
A sessionStorage boolean hides it in the current tab until the next successful
AJAX add-to-cart. Storage denial falls back to in-page dismissal. No cart contents,
prices or personal totals enter storage. AJAX fragments and own-session summary
remain the data source; desktop, cart, checkout, account and draft exclusions stay.
At <=360px the summary occupies its own row to keep controls readable.

Verification: `scripts/tests/checkout-comfort-local.php` runs real Woo CRUD with
synthetic local orders/customers, blocks HTTP and intercepts mail, then deletes
fixtures. Covers creation, existing retail/wholesale/staff profiles, duplicate
processing, same-phone/different-email, mail failure, private notice, actual and
forged/mixed rates, email and preserved errors. Browser acceptance covers the
native login form, pickup/delivery switch, cart hide/reload/next addition, narrow
phone and desktop layouts. No real checkout payment or inbox delivery was tested.
User-facing guide and account help are updated in Ukrainian and Russian.

Deploy together: PSU, `pc-guest-customer-register.php`, `00-mu-i18n-loader.php`,
`pc-wholesale-help.php`, help image and matching MU/plugin PO/MO translations.
